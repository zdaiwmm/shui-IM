# 2026-09-05 移动交互批次交付复盘

本页复盘的是从十余项移动交互、保险箱整理和消息删除需求，到合并、生产发布及知识库
对账的交付过程。目的不是降低产品、安全或生产门槛，而是减少下一批任务的无效等待、
重复验证和上下文消耗。精确功能与生产证据分别以 `PRODUCT.md`、`TEST_PLAN.md` 和
`RELEASING.md` 为准。

## 结论

这次交付成本过高，用户的反馈成立。主要问题不是服务器切换本身：成功的服务器阶段为
58 秒；成本集中在过大的单批变更、过晚暴露的跨平台测试夹具问题、一次外部依赖安装卡住，
以及发布隔离克隆的长等待。执行过程没有在开工时把需求拆成有明确停止线的风险批次，
也没有足够早地把失败分成产品、测试和基础设施三类，造成了不必要的完整回归和上下文往返。

## 可核对的时间与规模

- 应用 PR #17 改动 57 个文件，增加 7,548 行、删除 867 行；同时触及主界面编排、保险库、
  消息载荷、服务端投影、媒体手势、生命周期和多组浏览器测试。这已经超过适合一次性实现、
  审查和定位失败的理想批次。
- 冻结候选的本地 `npm run check:full` 通过 50 个 Vitest 文件、400 项测试和 23 个浏览器
  入口；浏览器部分为 200.34 秒。该完整结果有价值，但不应在每个小改动后机械重跑。
- PR #17 的最终完整 CI 成功；合并后的首个 main CI 才暴露回应气泡测试使用固定像素位移
  阈值的问题：Linux 字体回退下测得 4.920654296875px，而夹具要求大于 8px。产品仍满足
  300ms FLIP、首帧零跳动、DOM 保留和最终移除；这是测试可移植性问题，不是产品回归。
- 测试修正 PR #18 的首次 CI 在 Playwright 浏览器安装阶段长时间无进展后取消；同一提交
  重跑通过。最终 main 完整 CI 约 4 分钟通过。
- 固定发布入口第一次在生产调用之前的隔离浅克隆阶段等待 120,011ms 后超时，总计
  137,104ms；随后只读 SSH 探测 5.3 秒成功。安全重试的隔离克隆仍耗时 61,664ms，
  成功入口总计 145,543ms，其中实际隔离发布及入口回读 72,217ms、服务器阶段 58 秒。
- 用户明确反馈整体耗时和 token 消耗不可接受；系统没有为本记录提供可核对的精确 token
  总量，因此不编造数字。

## 哪些步骤必须保留

- 涉及删除语义、密文投影、设备邀请、保险库和生命周期的应用变更必须经过完整应用测试；
  定向测试只能用于加快反馈，不能独自授权发布。
- PR 审查、精确 main 提交验证、隔离发布、冷备份、维护门、健康检查、公开 WebSocket、
  `DEPLOY_VERIFIED` 和独立 `READBACK_OK` 是不同证据，不能因为手工发布更快而混为一步。
- 合并后 main 全量 CI 当前是固定发布入口的硬门。只有未来实现并审阅“PR 已测源码树与
  merge 提交源码树一致”的不可伪造证明，同时更新发布策略和自动回归后，才可讨论复用
  PR 结果；本次不能绕过。

## 本次应当做得更好的地方

1. 开工时先建立按风险域分组的验收矩阵，并冻结范围：邀请/设备，媒体查看器，
   键盘/输入栏/系统弹窗，回应/回复/删除，保险箱本地整理。跨组共享的协议或生命周期
   修改单独列出，任何新增需求先判断属于当前批次还是下一批。
2. 每个风险批次先跑类型检查、单元测试和一个最小浏览器专项；所有批次集成且代码冻结后
   才跑一次本地全量。只有产品代码、共享测试基础设施或发布候选发生实质变化时才重新全量。
3. 第一次失败先分类并留下证据：产品失败才改产品；夹具失败只改测试；下载、排队或网络
   卡住只处理基础设施。没有分类前不同时改产品代码和断言，也不启动另一轮全量。
4. 几何测试避免依赖 CJK、emoji 或系统字体的绝对像素。优先验证首帧无跳动、相对位置、
   动画时长、最终状态、元素保留和 reduced-motion；必须测距离时使用由当前行高推导的阈值，
   并把实测值、行高和状态一起输出。
5. 发布入口在开始 120 秒克隆前应做同协议短超时探测；克隆应提供阶段进度，并只在确认
   服务器尚未被调用时允许有限重试。评估 Git protocol v2、按提交浅取或安全的对象缓存，
   但必须继续从 GitHub 精确 main 创建隔离副本，不能复制脏工作树。
6. 用户更新只在范围冻结、完整 CI、合并、发布和回读等里程碑发送，明确当前证据层级、
   单一阻塞和下一步；避免重复叙述内部探索过程占用上下文。

## 后续可执行改进

- 为大批需求增加“风险域、验收 ID、定向测试、全量触发条件、是否需要真机”的短表，并在
  编码前完成一次范围确认。
- 为 GitHub Actions 缓存与 `package-lock.json` 绑定的 Playwright 浏览器包；安装超时要输出
  下载阶段，基础设施重跑不得掩盖测试失败。
- 为浏览器夹具增加跨字体准则：目标元素强制进入视口、避免依赖字形高度的固定阈值、失败
  输出诊断几何；CI 至少保留 Linux Chromium。
- 为 `publish.mjs` 增加 GitHub SSH 克隆通道的快速预检、可观察进度和“仅在服务器调用前”
  的一次有界重试；各阶段继续输出 `RELEASE_TIMING`。
- 单独设计并审阅 CI 结果复用方案，量化“PR + main”重复测试的时间收益与供应链风险。
  在方案落地前维持精确 main 完整 CI 门禁，不以手工经验替代证据。
- 下一次同类批次以“成功路径一次完整本地回归、一次 PR 完整 CI、一次 main 完整 CI、一次
  固定发布、一次独立回读”为目标；任何额外轮次必须能指向明确的产品、夹具或基础设施原因。
