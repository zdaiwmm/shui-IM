# iPhone 输入与发送抖动：本地修复证据

日期：2026-09-07。基线：`eac6a509c477064daf17dc8514ba3fc2f6b23602`。
任务分支：`codex/iphone-input-jitter-20260907`。仅本机开发与局域网验收，不代表生产。

## 真机故障证据

用户提供 iPhone／iOS 27／Safari，通过 USB Web Inspector 连接本机 HTTPS 开发页面。
采集只包含视口、滚动、元素矩形、输入事件类型、消息数量与显隐状态，不读取消息文本、
房间凭据、邀请、恢复材料或附件。手机页面刷新后由临时开发中间件重新挂载采集，
采集代码不进入应用构建。成功采集段含 9 次 submit 事件（其中一次未增加消息行）。

- 多行输入时，固定区域坐标变化先于视口数值，出现约 21／23 CSS px 偏移。
- 发送时，滚动补偿仍保留在旧目标上，出现约 48／49 CSS px 偏移后回正。
- 收键盘时，标题栏出现约 341／376 CSS px 下落；失焦后的旧校正不再持续，
  而 `visualViewport` 仍保留键盘端点，数百毫秒后才归零。

以上为几何采样证据，包含事件与 rAF 回调时点，不能把每条中间样本都等同于已绘制帧。
用户同时报告明显抖动。旧发布记录中的较早专项真机证据不覆盖本轮完整输入序列。

## 修复范围

触屏 iOS WebKit 从未做位置动画的标题栏矩形减去自身 translate，取得当前原生固定定位
原点；每个聊天可见帧以及程序滚动后均由同一定位函数校正。移除滚动差值预补偿、
120 ms 复位与 240 ms 固定目标校正之间的竞争。失焦与无 viewport 事件的帧仍覆盖。
输入工具栏的 14 px 显现 transform 不计入持久 bottom；消息可见范围与阅读锚点使用
对应的 client 坐标。保留 280 ms 输入伸缩／列表动画、历史阅读锚点与运动期间隐藏门槛。

## 复测后的顺序修正

首版真机采集含 6 次 submit。多行发送收尾出现约 66 CSS px 来回偏移；历史位置发送还出现
大幅反向滚动。空草稿的真机临时实验进一步确认：输入框收缩使文档底部 padding 减少，
Safari 自动钳制 scrollY，同时原生固定定位原点变化。旧顺序在修正输入栏前计算滚动目标，
把这次自动钳制重复计入了一次滚动。实验只写入临时测试草稿，未发送消息，结束恢复空草稿
和原阅读位置；日志只有数字，不保存文本。

- 首版收缩：浏览器先从约 1607 自动钳制到 1541，代码再请求 1474.52，下一轮又请求 1540.52。
- 手机内存对照：先修正固定区域再读目标，收缩只剩浏览器自己的钳制，没有额外的两次反向请求。
  标题维持 0 px，输入框底边维持原位，最后消息允许整数滚动取整带来的 1 px 误差。
- 历史位置的程序化多行展开实验中，同一可见气泡位置与 scrollY 保持不变；这不等于真实中文
  IME 连续输入已通过。后续采集补入可见气泡、消息行矩形、textarea 内部滚动和选区数字。
- 第二轮修正将固定区域校正提前到布局变更后、读取滚动目标前；静止的 composer 不保留
  transform 或 will-change: transform，以减少原生光标与祖先合成坐标不一致的条件。
  光标效果与用户报告的历史位置输入仍需真机确认。

第二轮 Chromium／桌面 WebKit 布局专项通过；新增原生钳制断言在首版实现上失败（出现不应有的程序滚动）。最终全量结果待记录。


## 底部编辑与原生光标

第二轮用户反馈历史位置输入貌似已正常，底部输入仍抖。增强采集显示内部 scrollTop 保持 0，
但逐帧增高 textarea 时，新行所需的 scrollHeight 已增加，真实 clientHeight 仍处于较小的
中间值。为消除原生光标与 JS 编辑区域动画争用，触屏 iOS 聚焦输入改为在 input 事件内完成
textarea 高度；消息内容单独从当前可见位置过渡 280 ms。原生光标不替换、不隐藏，不重设
组合输入选区。其他浏览器保留原有字段高度动画，键盘显现动画保持不变。

新增原生编辑夹具在 Chromium／桌面 WebKit 通过：编辑区立即容纳新行、焦点和选区不变、
后续帧字段高度固定、消息保持动画、历史阅读位置不动。第三轮用户确认光标正常，但仍有抖动。

第二轮全量验证的主浏览器入口出现一次相册返回锚点偏差（同一消息相差 88 px），因此该轮
全量未通过；未修改断言。独立首版基线副本的同一入口通过，候选的单独复核通过，失败未稳定复现；最终全量继续保留同一断言。


## 应用帧之后的原生定位变化

第三轮增强采集把残余偏移对齐到标题和输入栏：换行约 21 px、发送约 48 px，且出现在应用
已经校正位置之后，下一应用帧才归位。历史位置发送可出现更大的同类位移。继续提高同一
固定原点反馈的频率不能证明能拦住这一时机，因此增加了独立坐标方案的真机内存对照。

用户准备好输入框后，临时将键盘打开期间的标题和 composer 定位到消息文档坐标。
展开与收缩 61 个后帧样本中，标题 top 范围为 [0, 0]，输入布局底边保持 319 px；浏览器随后
从 offsetTop 376 更新为 309 未产生标题偏移。实验不发送消息，原草稿、选区和阅读位置仅在
手机内存暂存并恢复。该对照不是最终完整交互验收。

当时的实验候选只在触屏 iOS 键盘打开期间采用绝对文档定位，键盘关闭恢复 fixed；所有浮动提示
与标题、composer 使用同一坐标。新增晚到原生坐标回归在独立首版基线副本失败，候选的
Chromium／桌面 WebKit 布局专项均通过（20 组），包含输入区同步布局、原生钳制和键盘切换。
最终全量和用户复测结果待记录。

该实验全量日志虽最终显示 24／24 浏览器入口通过，但运行尾段发生了回撤，源码不再冻结，

## 标题与浏览器底部工具栏

延长原生 sticky 对照后，采集记录到 20 次焦点开合事件，用户明确回复标题“不会了”。
短时对照未发生键盘操作的样本不作为通过证据。标题改为原生 sticky；独立不可见探针测量
固定坐标，标题不再参与固定原点的脚本平移反馈。

用户又报告滑动停止后输入栏被浏览器底部工具栏遮住。原生截图与日志对应到可视高度
735 px、clientHeight 695 px、composer bottom 775 px：旧计算设置 bottom=-40 px，额外
下推 40 px。组合候选新增独立的固定底边探针，composer 使用实际底边减可视高度；新增
原生底边扩张、布局高度不变的回归，WebKit 专项通过。最终完整门禁与组合真机结果待记录。


## 键盘开合联动候选

sticky 与独立底边探针组合的完整门禁通过：464 项单元／集成、24／24 浏览器入口，
浏览器总计 277.85 秒。用户组合真机反馈为“关闭键盘时标题栏会跳，输入栏位置正确”；
因此不将较早的 sticky 对照成功外推为所有键盘路径通过。

用户进一步明确：收键盘时底部消息随键盘下移；弹起时从历史位置快速定位到最新消息，
末条位于输入框上方。本候选从 blur／松手开始保留相对消息位置并作短时下移，待动画
与视口稳定后再转换文档滚动；原生键盘可能只暴露最终 viewport，当前 280 ms 曲线为
候选，不能仅凭脚本断言宣称与系统动画逐帧同速。弹起在首个打开视口采样提前贴底。

新增关闭中间帧、早／晚视口事件、最终底边、历史关闭、再次聚焦和生命周期取消回归。
提前贴底首轮专项发现留白基线仍保留关闭值，切回原生滚动时发生裁切；已调整为在提交
新视口留白时同步跟随状态的恢复基线并保留缓冲。最终专项、完整门禁及组合真机待完成。


首轮开合联动的完整门禁通过（464 项、24／24 浏览器，303.70 秒）；用户真机确认弹起时及时到
最新消息且不遮挡，同时反馈收起不够贴合、标题展开时消失、输入栏显现慢。采集证实 sticky
标题在原点偏移 376 px 时位于可视区域之外，候选新增独立探针原点到 sticky top 的映射，
无需标题自身位置反馈。专项夹具同步补齐已被真机证实的 sticky 可视原点位移，保留顶部为零断言。

同页八次 blur 到关闭视口更新约 424～444 ms，原 280 ms 消息曲线过早完成；新候选改为
420 ms 缓出，并将关闭态 composer 最小高度／底部留白差计入终点，避免约 6 px 的最后校准。
原生关闭端点只追加 32 ms 偏移稳定时间，输入栏改为原位 120 ms 淡入，不再附带 14 px 下滑。
新增单位回归确认该短等待不会提前显现中间键盘几何；18 项 viewport 单位回归通过。
最新候选仍需组合专项、完整门禁和真机反馈，不能将首轮通过转记到最新源码。


时序调整后用户确认标题持续可见，但仍闪动，消息下移未更顺滑、输入栏仍偏慢。
去掉脚本消息动画的真机对照被用户明确描述为“停住后才跳”，排除单靠原生页面移动即可跟随。
焦点来源采集显示部分 focusin 是消息 ARTICLE 接收焦点，并非 textarea 被脚本反复聚焦；
不据聚合 focusin 日志误改输入焦点归属。

当前候选改用消息列表的 Web Animations translate 合成动画；只有原生原点或文档位置变化时
才调整相对 top，平稳帧不重排列表。键盘最终关闭几何不再追加稳定延迟，输入栏直接在终点显现。
构建、18 项视口单元及 WebKit 专项通过。用户确认输入栏能及时出现；下移有时流畅有时不流畅，
标题仍闪，因此仍未完成真机验收。当前正在做仅标题 fixed/top=0、无脚本补偿的独立对照。
