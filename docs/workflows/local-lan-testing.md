# 本机局域网测试与跨电脑同步

本页定义 Quiet Room 在家里和公司分别运行本机测试环境的固定流程。GitHub 只同步代码、测试、文档和非敏感示例；每台电脑独立保存证书、主机名、测试数据和设备保险库。

## 状态分层

- **任务工作树候选**：改动只存在于独立任务分支，不能视为本机测试环境已更新。
- **本机 main 已集成**：精确提交已进入当前电脑的本机 `main`，仍不表示 GitHub、另一台电脑或生产已更新。
- **本机服务已回读**：实际局域网前后端进程从本机 `main` 运行，前端加载目标代码且后端健康。
- **真机验证通过**：记录设备、系统、浏览器、HTTPS 来源和通过范围；不能由自动化或服务回读代替。
- **GitHub 已同步**：任务经远端流程进入 `origin/main`，另一台电脑可拉取；仍不表示生产已发布。
- **生产已发布**：仅由固定发布入口与独立生产回读证明。

## 在当前电脑开发和验收

1. 从核实过的基线创建独立 `codex/<任务>` worktree；共享 `main` 目录仍只用于接手、集成和运行本机测试服务，不直接编写改动。
2. 在任务 worktree 中复现、修改、运行风险匹配测试并提交，记录候选 SHA 和变更范围。
3. 准备本机验收时，重新核对共享目录确实位于 `main`、工作树干净且没有归属不明内容，并固定要集成的任务提交。
4. 候选是本机 `main` 的直接后代时使用 `git merge --ff-only <任务分支>`。不能快进时，在独立集成 worktree 处理组合和冲突并复验；不得覆盖、重置或暂存共享目录中的用户改动。
5. 集成授权仅更新本机 `main`。除非用户另外明确要求，否则不 fetch、pull、push、创建 PR、修改远端 main 或发布生产。
6. 集成后记录本机 `main` 的精确 SHA，并按下一节核对实际服务。代码进入本机 `main` 但服务仍从旧 worktree 或旧构建运行，不能写成测试环境已更新。

## 局域网服务回读与重启

先发现实际运行状态，不假定上次端口、临时 Vite 配置或证书路径仍然有效。至少核对：

- 局域网 HTTPS 前端和 API 后端均在监听；
- 两个进程的当前工作目录都是共享本机 `main` 目录，而不是旧任务 worktree；
- 前端源码或构建版本回读包含目标提交的可识别变化；
- 后端健康接口成功，并使用本机测试数据而非生产数据。

Vite 开发服务通常会热更新前端 TypeScript、CSS 和 HTML；源码回读成功时不机械重启。以下情况只重启受影响的本机测试进程，再重新回读：

- 修改了 `server/`、依赖、环境变量、启动脚本或 Vite 配置；
- 进程工作目录指向其他 worktree；
- 前端仍返回旧源码、代理失败或后端健康检查失败；
- 使用静态构建／预览服务，目标提交尚未重新构建。

不得终止其他任务、生产代理或归属不明进程。进程存在、端口开放和页面能打开都不能单独证明目标提交已经加载。

## 通行密钥真机要求

- 手机必须通过稳定、设备信任且证书主机名匹配的 HTTPS 局域网来源访问。
- 不使用证书警告页、普通局域网 HTTP 或裸 IP 对 WebAuthn 成败下结论。
- WebAuthn 凭据绑定 RP ID（主机名），IndexedDB 与本机历史绑定完整来源；改变协议、主机名或端口可能进入不同的本机空间，不能把旧来源的数据存在当作新来源已完成配置。
- 家里与公司的测试数据、通行密钥、保险库和会话彼此独立。不要复制数据库、证书私钥、邀请、恢复材料或设备密钥来模拟同步。
- 修复后使用新页面和新生成的邀请复测；新增设备链接只有十分钟有效。

## 通过 GitHub 同步到另一台电脑

本机真机验收通过后，只有用户明确要求同步 GitHub 才进入远端阶段：

1. 推送任务分支，通过既有 PR／CI 流程进入远端 `main`；不得把局域网集成授权解释成直接推送远端 main。
2. 公司电脑开始工作前先检查未提交内容；有本地改动时不得覆盖或自动 stash。
3. 工作树干净时以快进方式更新本地 `main`，并核对本地 HEAD 与目标 `origin/main` SHA 一致。
4. 同步依赖后启动或重启公司电脑自己的本机测试服务，重复服务回读和真机验收。

GitHub 中只保存通用代码、自动测试、工作流文档和脱敏示例。以下内容必须由每台电脑单独配置，并保持在忽略文件或仓库外：TLS 私钥与本机证书、真实主机名与网络设置、测试数据库和附件、通行密钥与本机保险库、邀请链接、恢复材料、个人环境变量和临时目录。

## 交付记录

每轮分别报告：任务候选 SHA、本机 `main` SHA、自动测试、服务工作目录与回读、真机结果、GitHub 状态和生产状态。推荐措辞为：

```text
本机 main 已集成：<sha>
局域网服务已回读：前端目标代码 / 后端健康
真机：<设备、系统、浏览器、来源、结果或未验证>
GitHub：未推送 / 已推送 / 已进入 origin/main <sha>
生产：未发布 / 已发布并回读 <sha>
```

局域网失败时保留失败步骤和可见状态，从当前本机 `main` 新建下一条隔离修复分支；不要在共享测试目录直接热改。
