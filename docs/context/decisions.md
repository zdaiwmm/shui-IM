# Quiet Room 决策与不变量

本页记录对后续工作有长期影响、但仅看局部代码容易误解的决定。它不是聊天流水账。“仓库契约”表示由现有资料与实现支持，不等于用户在本次会话里重新确认了全部细节；下面的原因是依据资料归纳的工程理由，不冒充历史讨论记录。

## D-001：使用无账号、两人、独立多设备模型

- 状态：已采用，仓库契约。
- 决定：一个房间仅有创建者和受邀者两名参与者；每人最多三台活跃设备，每台设备拥有独立身份、令牌、MLS leaf/key package、通行密钥绑定和本机保险库。
- 原因：避免共享私钥，同时允许每名参与者授权自己的新设备并独立撤销。
- 重要后果：新增设备不能获得加入前历史；移除设备不能远程删除它已经解密到本机的历史。
- 依据：`README.md`、`PRODUCT.md`、`SECURITY.md`。

## D-002：新房间用 MLS，服务端只负责密文顺序与传递

- 状态：已采用，仓库契约；未完成独立密码学审计。
- 决定：新房间使用 RFC 9420 MLS。服务端验证外层身份、签名、配额和顺序，但不解密消息内容。
- 原因：提供成员变更和应用消息棘轮，同时让服务端能够做幂等、顺序、重连和资源控制。
- 重要后果：发送密文、更新后的 ratchet state 与待发箱项必须在一次 IndexedDB 事务中落盘；普通重试复用同一消息 ID 与密文。成员变更后，过期纪元的待发项按协议重新加密，不能把普通网络重试与该流程混淆。接收状态、本机历史和待签收回执也需要原子持久化。
- 限制：旧协议房间没有相同的前向保密属性；完整 post-compromise recovery 仍未实现或审计。
- 依据：`README.md` 的 Ordering model、`SECURITY.md`、`PRODUCTION_SECURITY_GATE.md`。

## D-003：正式来源固定为 ai.shui.click

- 状态：已采用，生产不变量。
- 决定：正式来源和 WebAuthn RP ID 使用 `https://ai.shui.click` / `ai.shui.click`，API 与 WebSocket 同源。退役的 `chat.mijiu.cloud` 不再作为兼容的本机保险库命名空间。
- 原因：通行密钥与 IndexedDB 都具有来源边界，换域名会形成不同的本机身份与历史空间。
- 重要后果：不得为迁移便利扩大 RP ID、加入宽泛 CORS 或让退役域名继续托管应用 JavaScript。
- 依据：`README.md`、`SECURITY.md`、`DEPLOYMENT.md`。

## D-004：隐藏入口是隐私遮罩，不是假装成安全认证

- 状态：已采用，仓库契约。
- 决定：浏览器加载失败外观、右下角长按和桌面 F 键只负责进入解锁网关；真正的本机解锁由 WebAuthn PRF 和系统用户验证保护。
- 原因：隐藏入口可以降低旁观暴露，但不能提供密码学认证。
- 重要后果：不得宣传其能阻止截图、系统缩略图、恶意扩展、受控操作系统或已解锁设备读取内容。
- 依据：`PRODUCT.md`、`SECURITY.md`。

## D-005：桌面便利恢复与移动严格锁定分流

- 状态：用户已确认并实现，安全文档已同步，已部署到生产；精确提交与验证范围见[状态页](./status.md)。
- 后续变更：用户发起的选择器和媒体授权仅对可见文档失焦的有界处理由 D-020 取代；真实隐藏、硬生命周期及桌面恢复期限不变。
- 决定：普通桌面浏览器失焦时立即显示遮罩并清理可见内容、媒体、传输和连接，但可把会话仅保留在页面内存中最多 30 分钟；移动、平板和安装型 PWA 仍严格锁定。原生选择器、导出、麦克风/摄像头权限、剪贴板、确认框、`pagehide`、freeze、显式锁定和超时不使用便利恢复。
- 权衡：桌面切换窗口时减少重复认证，但解密能力在内存中保留更久；移动/PWA 继续使用更严格策略。这是当前取舍的归纳，不是独立安全审计结论。
- 限制：屏幕宽度或是否有键盘不能用于把 iPad 判成普通桌面。活动通话只暂停移动端原有空闲锁；桌面仍以真实操作续期。
- 依据：`PRODUCT.md`、`src/app.ts`、桌面隐私/恢复专项测试。

## D-006：附件保留原始字节，普通文件不在应用内预览

- 状态：图片和语音为既有契约，普通文件能力已部署到生产；精确提交与验证范围见[状态页](./status.md)。
- 后续变更：下述“普通非图片文件不预览”中针对视频的限制被 D-014 取代；原始字节、完整校验、其他普通文件仅下载和语音标准化规则仍有效。
- 决定：导入的图片与普通文件不通过 Canvas 等途径改码，按原始字节加密，下载后验证原长度和 SHA-256。普通非图片文件只提供经验证的下载，不在应用内执行或渲染内容；图片保留既有查看器。语音录音另有端侧 PCM WAV 标准化步骤，不能误称录音片段完全未经转换。
- 原因：避免不可见的改码和内容执行面，保持发送与下载字节一致。
- 重要后果：附件元数据也属于加密负载；兼容性能力门必须在发送和待发重试时生效。
- 依据：`PRODUCT.md`、`README.md`、`SECURITY.md`、`src/lib/file-crypto.ts`。

## D-007：设备加入边界也约束回复与本地历史

- 状态：已采用，安全不变量。
- 决定：回复目标信息位于加密消息内，但可见引用内容只从当前设备已有的加密本地历史生成。没有原消息的设备显示历史不可用，而不是由新回复夹带旧内容。
- 原因：防止用回复机制绕过新设备的硬历史边界。
- 依据：`PRODUCT.md`、`README.md`、`SECURITY.md`。

## D-008：送达、在线和未读分别表达不同事实

- 状态：已采用；未读首次注册语义已与安全文档统一。
- 决定：服务器已保存、对端设备已验证并持久化、设备是否报告在聊天页、用户是否看见消息是不同事实，不能相互替代。
- 原因：避免把网络连接、服务端观测或密文同步误称为人已经阅读或安全接收。
- 重要后果：presence 不是身份或注意力证明；首次建立未读观察凭据不能把“已下载到本机的密文”直接当作“已可见阅读”。
- 依据：`PRODUCT.md`、`SECURITY.md`、`src/lib/unread-counter.ts`、未读相关测试。

## D-009：通话与聊天使用不同的安全声明

- 状态：应用代码已部署到生产，产品/安全契约见 `CALLS.md`；生产中继与公网真机验收进度见[状态页](./status.md)。
- 决定：通话信令负载进行加密和签名，服务端只做临时路由与仲裁；媒体由 WebRTC/DTLS 保护。通话信令的静态设备 ECDH 不承诺设备长期密钥泄露后的前向保密。
- 原因：通话是短时、实时、点对点媒体协商，不等同于 MLS 持久消息历史。
- 重要后果：不能把聊天 MLS 的前向保密、安全审计或历史边界表述直接套用到通话；TURN 会额外观察网络与流量元数据，且真实公网和真机能力必须单独验收。
- 依据：`src/lib/call-crypto.ts`、`server/calls.mjs`、当前通话测试和部署覆盖。

## D-010：发布必须固定提交并与开发工作树隔离

- 状态：已采用，运维不变量。
- 决定：只有用户明确要求发布并确认完整的 GitHub `main` 提交号后，才使用 `node scripts/publish.mjs --sha <40位提交号>`。入口等待目标 CI、建立独立临时发布副本、发布并回读线上提交。
- 原因：避免把本地未提交或并行开发内容带入生产，并让上线版本可追溯。
- 重要后果：发布入口不负责替用户合并代码；GitHub main 变化、CI 失败、目标不明或生产回读不符时停止。
- 验证分流：仅知识库白名单和发布记录变更可走文档轻量 CI；发布仍要求精确 main SHA 的最新 push 或手动 CI 成功，且完整应用汇总任务成功。文档轻量结果不能替代完整应用验证，手动完整检查也不构成发布授权。
- 依据：`RELEASING.md`、`DEPLOYMENT.md`。

## D-011：高安全声明以外部验证为门槛

- 状态：阻塞中。
- 决定：在 `PRODUCTION_SECURITY_GATE.md` 的独立密码学/应用审计、真机矩阵、灾备、推送、SLO 和运营门槛完成前，不把当前系统宣传为经过独立验证的高安全服务。
- 原因：采用成熟协议与具体实现通过独立验证是两回事；网页来源本身仍能替换客户端 JavaScript。
- 依据：`PRODUCTION_SECURITY_GATE.md`、`SECURITY.md`。

## D-012：创建者保险箱默认隐藏图片

- 状态：用户明确要求，已部署到生产；验证范围、目标提交与仍待真机验收的部分见[状态页](./status.md)。
- 后续变更：下述“图片”分类名称及仅含图片的范围被 D-014 取代；入口“保险箱”、默认模糊、首次显露再次打开和访问内存边界继续适用于相册中的照片与视频。
- 决定：创建者相册入口改名为“保险箱”。每次进入默认模糊图片，首次点击显露单张，再次点击使用现有查看器；通过眼睛图标显示全部／隐藏全部，离开或锁定后重置。图片与文件通过单行标题栏的等高分段控件切换，数量弱化置于各自分类；不展示额外标题、缩略图提示或时间，时间在放大后的详情中展示。
- 边界：显露状态只存在于本次访问内存；模糊是已解锁页面内的视觉遮挡，不增加认证能力，不更改创建者权限、原始附件字节或现有加密协议。
- 依据：本次用户需求、`PRODUCT.md` 的 Creator Safe、`SECURITY.md` 的本机缩略图说明、`src/app.ts`。

## D-013：自动密文备份、恢复后换码，服务器不托管恢复码

- 状态：用户明确确认；主站自动备份已部署，后台代码随版本提供但 `admin-enabled=0`。精确应用版本、验证层级及待办见状态页。
- 决定：按会话/参与方/设备管理自动加密备份。QR3 码自动定位备份并本地解密；服务器和后台不保存恢复码。仍可用设备允许重新验证通行密钥后查看本机加密保管的当前码。
- 恢复：沿用可信设备协助的 MLS 替换，生成新设备身份。完成替换后立即持久化新码保护，保留全部历史归档密钥，幂等上传并原子停用旧在线入口。历史和创建者保险箱由用户主动要求并再次输入新码恢复；保险箱单独恢复不产生旧聊天预览。普通新增设备不获得这些秘密。
- 后台：`sao.shui.click`，强密码加 TOTP，只有会话/设备/备份元数据及经再次验证的清理功能；生产尚未启用，需完成域名、TLS 和管理员初始化。之前讨论的管理员恢复码托管方案已被用户撤回，不得恢复该设计。
- 边界：前台备份可能滞后；码与设备均丢失接受重建。旧码与旧密文副本仍可离线解密；网页来源攻击不因这套备份解决。手动恢复 JSON 上传/下载入口移除，旧 QR2 材料需要在切换前迁移。
- 依据：`RECOVERY_BACKUPS.md`、`PRODUCT.md`、`SECURITY.md`、`DEPLOYMENT.md`。

## D-014：视频本机预览与播放，保险箱使用照片和视频相册

- 后续变更：优先打开页面播放器的方式被 D-018 的原生全屏优先取代；完整性、原始字节和创建者权限边界保持。

- 状态：用户明确要求；完整 CI 已通过并部署到生产，精确应用提交与回读证据见[状态页](./status.md)。真实设备验收仍未完成。
- 决定：聊天视频像照片一样展示预览图和播放按钮，点击后进入页面满屏查看器并请求播放，保留浏览器原生播放控件。浏览器拒绝自动播放时可再次点击播放；不可解码的视频仍可下载完整校验过的原文件。页面满屏不承诺操作系统原生全屏模式。
- 相册：保险箱中的“图片”改为“相册”，包含聊天照片、聊天视频和直接上传的照片/视频。已有兼容的视频 `file` 消息也纳入相册，`gallery-file` 视频从“文件”归到“相册”；其他聊天文件仍只留在聊天，直接上传的其他文件仍留在保险箱“文件”。每次进入默认模糊，第一次点击显露、第二次打开查看器，视频第二次点击请求播放。创建者权限保持原规则。
- 附件边界：复用既有 `file` / `gallery-file` 密文格式、能力门及加密传输，原始字节不转码。全部分片认证、原长度与 SHA-256 校验通过后，端侧解码生成内存中的 JPEG 起始预览帧；预览不持久化、不上传、不替换原件。关闭或翻页停止播放并移除播放器来源；锁定与隐私清理还须取消预览任务、清除媒体缓存并撤销对象 URL。其他普通文件继续不在应用内执行或预览。
- 历史边界：相册的本机分类也适用于已有视频；显式单独恢复保险箱时可恢复照片和视频，但不生成旧聊天气泡或可引用的旧聊天预览，不改变普通新增设备的历史边界。
- 取舍：在已有图片解码之外允许端侧视频解码，增加浏览器媒体解码器的使用范围；完整性校验只能证明文件与发送原件一致，不能证明文件对存在漏洞的解码器安全。本项取代 D-006 的视频预览限制和 D-012 的“图片”分类名称/范围，不变更二者其余约束。
- 依据：本次用户需求、`PRODUCT.md` 的 Creator Safe / Video Attachments、`README.md`、`SECURITY.md`、`src/lib/video-media.ts`、`src/lib/video-poster.ts`。

## D-026：键盘目标态提交与一次性原生焦点交接

- 状态：用户以真机录屏明确要求消除点输入框时的整页白屏、标题抖动和收键盘时工具栏居中；已由 PR #24 合并，2026-09-06 完成本地全量、精确 PR/main CI 与生产独立回读，精确证据见[状态页](./status.md)。录屏是缺陷证据，不是修复后的真机验收。
- 视口：键盘几何分为关闭／中间／打开三态，并从上一个稳定端点的显著位移推断开合方向，因此 resize 先于 focus／blur 时仍携带目标态。中间高度即使静止超过 160ms 也不提交列表布局或显现输入栏；只有目标态自身稳定后，才在一个端点批次内提交最新留白、布局变量、贴底与向下按钮测量，再从最终位置显现。没有任何几何变化的硬件／浮动键盘可在 640ms 回退；已开始移动却未到终点不能使用短回退，原生过渡以整段 1.6 秒为上限，包含无方向的中间态抖动；手指按住及手动惯性仍等待释放与静止。首次中间态挂载保持隐藏，挂起恢复从首个新样本重新计时，离开期间输入事件不能重建键盘目标。原生视口事件按动画帧合并，过渡中只移动固定栏，标题不参与淡出或位移动画；被门禁延后的滚动分页、阅读锚点、已读和按钮测量在稳定端点结算一次。
- 原生焦点：仅移动端用户直接、可信、主指针点按当前聊天 textarea 且键盘原为关闭时，可创建一次、最长 1.2 秒的键盘前台交接，以吸收 Safari 打开原生键盘时的一次可见 `window.blur`。点按后的新键盘几何证据与第一次归属 blur 可按任意顺序到达，二者共同结算；窗口 focus 返回可单独清理，而只有 resize 证据时仍保留 owner 等待可能到来的 blur。程序化聚焦不授权。第二次失焦、已消费交接的双时钟超时、hidden、pagehide、freeze、持久 pageshow、显式锁、空闲到期、页面／会话／输入框变化仍走同步遮挡与锁定；未发生失焦的闲置 token 到期只清理。选择器和媒体授权只会清除并替代未消费 token；若键盘 owner 已消费 blur，新的原生 owner 冲突会失败关闭，所有权不叠加。
- 权衡：浏览器不提供可信的失焦原因；因此用户点输入框后的极短窗口内，真实但仍被报告为 visible 的窗口离开可能等到 1.2 秒硬期限才遮挡。任何 hidden 或硬生命周期信号仍立即失败关闭。这是为消除录屏白屏而采用的有界可用性取舍，不是认证或“始终在前台”的证明。

## D-029：线上反馈的验证唤起、手势几何与本机媒体密文复用

- 状态：用户在 PR #28 发布后以线上真机反馈明确要求；当前隔离工作树实现与证据层级见[状态页](./status.md)，不把自动化外推为修复后真机通过。

- 验证唤起：遮蔽长按进入 v3 网关后仍只在真实聚焦、可见且当前入口有效时调用 WebAuthn。针对 Safari 只更新 `document.hasFocus()` 而不派发 `focus` 的前台返回，发起前增加最长 1.5 秒的短轮询；WebAuthn 已返回但 Safari 延迟报告焦点时，同样保持遮蔽并最多等待 1.5 秒真实回焦后才消费结果。两处都不以计时替代真实焦点。轮询结束仍保留原生命周期受控的正常焦点监听和可重试按钮。锁定、隐藏、pagehide、freeze、入口替换及 65 秒验证期限继续失败关闭；网页不能强制浏览器自有通行密钥弹窗。

- 本机密文复用：网络取得的附件分块本身已经是 AES-GCM 密文，可按房间／附件／分块保存在 IndexedDB；锁定仍同步清除解密 Blob、缩略图、视频海报和对象 URL。再次解锁时从本机密文重新执行逐块认证、原长度和完整 SHA-256 校验，损坏或不完整缓存删除后只回源重建一次；浏览器配额淘汰只导致再次下载。该缓存不持久化附件密钥或明文，不改变服务器、设备历史、恢复和删除语义。
