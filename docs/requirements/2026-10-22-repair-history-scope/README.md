## 方案与验收

- 新随机本机主密钥必须拥有独立的加密记录范围，避免同房间不同保险库混读。
- 仅使用已解锁的本浏览器保护验证原保险库、房间／创建者／角色及完整历史投影；不把链接当作历史能力，不读取其他角色或活动设备的历史。
- 关联历史时保留原保险库及出错槽位，在新槽位保存当前授权的会话与经验证的历史归属；保留原密钥、密文、原文件、归档及草稿，不清理、不忽略损坏的撤回记录。
- 已经受影响的同浏览器会话也需核验原所有者后恢复读取；缺失、歧义、篡改或旧保护无法验证时保留现场并失败关闭，不能宣称找回。
- 验证先新建另一密室、原目录不可见、邀请方离线、打开链接、上线接替、双端收发及刷新；验证撤回投影、原附件、旧待发不重放、取消／锁定／陈旧写入和所有原记录保留。

## 实现与当前证据

- 根因负例已在真实IndexedDB复现同序号161报错；新密钥建立新槽位而记录仍以roomId索引，旧加密记录被新密钥读取，严格投影在接替完成后拒绝打开。新建另一密室不会自动删除旧槽位，原目录不可见不等于记录被清除。
- `createVaultLocked`在新主密钥产生时分配随机独立记录范围。正常保存不改范围；经本机认证的原所有者在新槽位复用其原密钥与范围，原保险库和出错槽位原样保留。不从链接导入旧密钥，不重放旧身份待发箱。
- 所有者发现只读取最多256个本机槽位标识，逐个解密本浏览器保护的v3新密室，验证房间／创建者／角色，排除其他活跃端，严格扫描三类历史存储。不同所有者不凭时间挑选；同一密钥／范围的损坏或缺失检查点不能被较早快照绕过。写入在同一事务校验原所有者、当前会话及本浏览器保护版本，取消可中止已发起事务。
- 桌面完整双端路径已通过，包含原聊天、撤回、原附件逐字节解密、原归档及草稿归属；原槽位和新建另一密室的槽位逐字节不变。已安装错误会话在刷新后可自动核验并另存关联，原错误槽位也保持不变；真机未连接。
- 实际IndexedDB覆盖独立主密钥隔离、所有者／原密文保留、角色／创建者／其他活跃端拒绝、晚到结果及写事务取消无半写、陈旧会话拒绝、撤回密文篡改及丢失、较早检查点不绕过。标准双端用例继续覆盖完整大附件自动备份、原设备待发不重放和恢复卡。
