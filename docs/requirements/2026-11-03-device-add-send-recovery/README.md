# 添加本人设备中断后自动恢复发送 V1

2026-11-03，用户报告主站原设备生成链接、PC 进入页面但未加入，次日原设备发送提示设备变更尚未确认。用户在本次会话要求修复现有用户，无需联系当事人操作。已确认客户端自动核对方案。未提供可共享的消息定位。非页面修复，无原型。规则与基线 `507d9a31`，实现分支 `codex/device-add-send-recovery`。

原版本在发起端先持久化 MLS Add，再发布。若请求未提交，过期候选会在服务器清理，本地 Add 仍可能阻塞密钥窗口轮换。浏览器测试在旧基线复现消息无法送达，未读取当事人设备或生产房间状态。

正常待发重试核对当时的同一笔本人设备 Add。服务器先清理过期申请，再返回房间状态。已提交的事件仍走原有完整验证及后继状态安装。仅在目标已从名单消失、当前完整事件链没有该目标或该事件，且原邀请已过期时，丢弃未提交的准备状态并继续原待发。网络失败或证据不足保留准备状态。旧端只持久化了候选而丢失链接时，候选创建后超过服务端允许的最长签发期限才可处理。无需数据库或保险库格式迁移。

验收入口为 `tests/message-window.e2e.mjs`。真实本地后端与两个隔离浏览器验证有效申请仍受保护，申请过期后对端收到同一待发，以及服务端已成功但原设备丢回执时正确安装成员变更。真实受影响设备未接入测试；完整门禁与集成进度见本需求 PR。生产需单独确认精确提交。
