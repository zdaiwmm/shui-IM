## 已确认方案与边界

1. 先使备份失败／新鲜度可观测，保留容量门禁，验证合成快照与隔离恢复。生产扩容、异地目标、告警实际送达与生产恢复演练另以真实证据验收；不能把代码交付写成备份链路恢复。
2. 协商按字节分页的消息同步；回执独立推进；成员先于消息。对单连接及全服务的发送和输入积压设限，关闭慢连接后从加密保险库的已持久化游标恢复。旧端的小页维持既有 500 条协议，超限明确要求升级，不能静默丢帧或无限重试。
3. 表情采集在下载前预约完整任务的保守字节预算，覆盖保留包、并发下载、解密和写库副本。保留最多十个逻辑运行任务，资源不足等待，取消／超时／关闭释放预约；不默认拆进程。
4. 本机三个加密历史存储用分页归并，比较同序号副本后释放普通消息，仅保留投影事件。仍严格解密全部记录、核验缺失与冲突，保留删除／已读／反应投影、新设备历史下界、已认证普通消息缺口和生命周期取消。没有明文索引或 IDB 版本迁移。
5. 用合成固定负载测量资源上限及历史对象保留；SQLite 全局计数器、进程拆分、持久化投影和大规模重构仅在测量证明净收益后实施。只抽取本轮边界明确的辅助模块。

不更换 React/PostgreSQL，不调整 MLS/AES-GCM、消息 ID 与重试密文、密钥／消息原子写入或产品隐私边界。容量与内存配置是保守初始预算，不声称已找到所有生产负载下的最优参数；不承诺固定延迟／RSS 降幅。
