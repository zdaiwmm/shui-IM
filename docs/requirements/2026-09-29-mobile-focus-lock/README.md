## 确认范围与事实

- 用户报告点击 iPhone Safari 键盘上方红框空白区立即进入遮蔽层；表情及保险箱照片／视频列表滑动偶发同类现象，且没有系统密码／通行密钥选择器。用户明确要求自行利用 USB 真机定位、给出可行方案并完成修复。
- 2026-09-29 USB iPhone16,1／iOS 27.2 上，已核对 Safari 当前标签为 `ai.shui.click`。红框空白区点击前页面可见且聚焦、键盘打开；之后同一页面仍可见但无焦点、键盘关闭并进入 `cover-mode`。当次 `window.blur` 事件顺序未完整采集，前后状态与未归属可见失焦锁定分支一致。错误标签页的截图不纳入证据。
- 真机表情列表的一次滑动只产生触摸与滚动，没有观察到锁定。现行代码在打开面板后立即清除刚建立的失焦归属，留有 Safari 延迟失焦的竞态。
- 真机保险箱当时只有一项，`scrollHeight === clientHeight`，无法复现长列表。静态代码确认缩略图条目常驻 DOM 的 `data-blob-id` 使 96 MiB 缓存驱逐失效；内存压力导致 Safari 重载仍只是待证假设，不能宣称是此次偶发锁定的已证根因。

## 修复行为与边界

- 仅在解锁聊天、当前输入框曾真实聚焦、原生键盘已开或刚在 600 ms 内收起、且没有应用内其他指针／焦点目标与系统选择器时，允许一次 2.5 秒的原生键盘栏可见失焦交接。若此前开键盘交接消耗过一次失焦，必须先观察到真实回焦；交接开始时 `document.hasFocus()` 必须为假。立即保持不透明隐私遮帘；只有页面真实回焦（包括可信触摸遮帘尝试恢复输入框焦点）才揭帘。第二次失焦、期限到仍无焦点、真实隐藏、`pagehide`、`freeze`、空闲到期、离开聊天及会话／输入框更换继续锁定。网页不能可靠辨识 Safari 原生栏，短暂保留解密运行期是有界取舍；失焦时不显示明文。
- 表情按钮的单次失焦归属保留到 Safari 延迟失焦或既有限时结算，避免打开面板后过早撤销；其余锁定边界不变。
- 保险箱滑出视口的缩略图卸载解码图像，并允许其媒体缓存被驱逐；重新滚入再加载。保留完整校验、默认模糊与显露状态，不改变附件原字节、加密历史、权限或服务端协议。单个超出上限的活动媒体和其他仍在 DOM 中使用的媒体仍可临时占用内存，不把缓存数字当作整个 WebKit 进程的硬上限。
- 不新增分析服务、会话回放、生产写入或自动发布。
