## 实现对照

| 流程 | 承载和实现 | 关键边界 |
| --- | --- | --- |
| A 创建 | 首页按钮直接创建；聊天壳承接未完成请求 | 本机先保存创建意图，响应丢失重用房间与身份；无前置锁 |
| B 邀请 | 聊天内复制按钮、toast、连接系统卡 | fragment 高熵秘密封装短链接，预览不消费，地址归首页 |
| C/D 聊天与引导 | 既有聊天和三步隐私引导、遮蔽设置／演练 | 连接卡是本机状态，不进入共享历史 |
| E 应用锁 | 既有数字键盘／实际 PRF、自动锁定页 | 随机浏览器主秘密被包装；移除自动解锁路径；锁不改变归档 |
| F 本机密室 | 既有设置列表、长按菜单与删除确认 | 目录、保险库、私有记录与原件原子删除；其他标签失效 |
| G 接替设备 | 既有设置浮层选择具体设备、复制链接 | 绑定目标和候选密钥；确认 MLS 提交才撤销旧端；其他端保留 |
| H 默认备份 | 备份总览状态与原位按钮 loading | 前台解锁联网执行；每块上传回读，清单最后提交，无卡也备份 |
| I 恢复图片 | 同一制作页内生成、保存、重新选择验证 | 长口令保护随机种子，原图恢复，不上传口令 |
| J 本机恢复 | 当前密室恢复表单及进度，成功返回聊天 | 正文暂存，全部验证后原子发布；失败不显示半份历史 |
| K 合并再备份 | 当前密室私有存储及本人归档 | 本人卡覆盖已完成再备份的旧历史；共享发送、回执、回复、通知隔离 |
| L 异常 | toast、原任务入口、原位 loading | 不追加错误页面；任务完成状态以真实提交为准 |

新归档独立取件，不要求原房间成员资格；服务器存密文、公钥和读取证明摘要。短邀请、归档、卡图片分别版本化。旧双人归档、助记词与 QR3/QR4 数据保留原规则，不转换、不清理。

审计修复包括：初次注册也需归档写入签名；同角色和同源房间才能重绑写入端；同浏览器接替保留本人历史材料；短链接 hash 变化可续入；重新生成链接废弃未完成候选且不提前撤销旧端；私有导入按来源去重、原子发布并保留删除事件；本机删除防止后台重建；新密室锁定不保留桌面免验证材料。
