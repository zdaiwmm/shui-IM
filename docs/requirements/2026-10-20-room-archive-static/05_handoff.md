## 必须保持的业务与安全契约

| 风险／冲突点 | 本稿处理 | 实施验收 |
| --- | --- | --- |
| 邀请短而可猜会占位或接替错误设备 | 不展示复杂口令，但链接内使用高熵随机秘密；一次成功加入后失效 | 预览、扫描和 GET 不消费；服务端原子消费；短有效期、限速、无秘密日志；密钥交换认证绑定邀请能力，不能只靠服务器替换公钥 |
| 地址归首页被误解成清除痕迹 | 只替换当前地址记录 | 不能承诺清掉系统历史、剪贴板或外部社交软件中的原链接 |
| 自动备份被误解成服务器能解密 | 内容在客户端加密，恢复私钥不交服务器 | 认证加密、唯一 nonce、权限绑定、附件及索引完整性、恢复公钥真实性都需实现验证；普通双方内容是分别封装，不是两人必须共同解密 |
| 导入旧记录泄露给新对方 | 本地归属于目标密室，云端进入目标归档的本人私有部分 | 正文、附件、索引、下载能力、预览、摘要、回执和通知均隔离；不能只藏 UI；恢复身份不自动关联为当前对方 |
| 本机完成被误写成一张新卡已全部覆盖 | J11 与 K03 分开；附件完成和私有清单提交为门槛 | 重试幂等，失败保留缺口；响应丢失查询同一任务；源归档消失不破坏已完成迁移 |
| 重复导入和跨房间去重误删 | 按原消息身份与来源去重，保留作者证据 | ID 带来源域；无法证明属于本人时不得直接标“我”；不覆盖原文、作者或时间 |
| 旧浏览器仍有缓存 | 同房间只更新连接资格；不同房间新增条目 | 不清旧历史、恢复材料、别的房间；有全局锁时先解锁 |
| 手机／电脑类别不能稳定标识设备 | 邀请绑定参与者、具体设备及其版本；同类多台显式选目标 | 类型识别仅引导；提交前准备失败不能踢旧设备；未知提交结果不能盲目重试 |
| 删除后后台又写回 | 删除标记、取消任务、标签页同步、本机清理独立于网络 | 中断续清、未完成不报成功；删除最后一房间不自动关闭全局锁；备份与对方保留 |
| 长期保留被理解成绝不丢失 | 不设到期；容量不足显示失败 | 不静默回收旧对象；长期灾备、回滚检测和恢复演练属于实施运维验证 |

## 三个凭证边界

1. 应用锁负责本浏览器主密钥和目录访问。无锁时随机加密仍存在，但浏览器自动解锁能力也存在，不能宣称抵抗同机访问。设置后需移除旧的自动解锁路线，不是只遮住页面；修改锁不换归档身份。
2. 恢复卡为归档读取能力，用独立长口令保护。图片复制后可被离线猜测；页面限速不能解决。卡片应版本化，随机盐与慢速 KDF 参数需基准测试，认证加密参数需严格校验；不能执行图内脚本和 URL。卡片不是持续增长的聊天数据文件。
3. 聊天设备凭证管理实时成员资格。替换设备不撤销它已读的历史或保存的恢复材料；当前卡不授予发消息能力。对泄露恢复材料进行未来备份密钥轮换，尚未作为本轮已确认功能，不得把普通接替描述为“完全踢出全部历史和未来备份”。L07 / M03 明示此边界。

应用锁六位数字的离线强度有限；设备验证只有在能实际保护解密材料时才能作相同承诺，不能把一次验证结果布尔值当作加密能力。浏览器恶意脚本、失陷端、已解锁端和系统残留不被静态原型解决。本轮未运行密码学或渗透审计，不能得出“无漏洞”结论。

技术边界参考：[Web Crypto 安全考虑](https://www.w3.org/TR/webcrypto/#security-considerations)说明 API 并不消除脚本和应用安全问题；[RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)提供内存困难口令派生依据；[OWASP HTML5 Storage](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#storage-apis)说明本地存储与脚本访问风险。这些参考不是对本产品实现的认证。
