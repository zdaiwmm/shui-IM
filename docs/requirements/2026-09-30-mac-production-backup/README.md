# Mac 主动拉取生产备份 v1

## 身份与方案

- 阶段：已确认实施，开发与验收中。规则来源 main `509444485ca49bd12b659d599476253a3a0d9ab3`。
- 基线：GitHub／origin/main `419edc61dddb80509fb33ce4323386d93f7d7b25`；分支 `codex/mac-production-backup-20260930`，独立任务 worktree。无页面，用户明确不需要原型。
- 现状：服务器根盘约5.30GiB可用、约86%使用，未满足在线备份8GiB／低于80%门槛。SQLite约190MiB；现有备份tmpfs64MiB。Mac内置盘开启FileVault，已有发布前恢复点通过摘要独立重读与gzip校验；没有外置物理盘。
- 方案：Mac通过已有严格主机校验的SSH主动拉取。服务器只读在线SQLite快照到受限tmpfs，仅发送完成的附件密文块；Mac私有目录限容量、文件数、路径与总量，逐文件落盘校验，再独立验证SQLite、索引和完整摘要，原子发布后发送与会话／清单绑定的回执。服务器收到回执才刷新健康状态。
- local模式保持原有8GiB／80%门槛；mac-pull模式把完整备份容量门槛施加在Mac目标盘。服务器临时数据库上限256MiB，tmpfs384MiB、备份容器内存512MiB。过大失败，不放宽上限或假造成功。
- Mac每12小时启动任务，睡眠后登录／唤醒由launchd补跑；一小时截止、互斥防重入。Mac不可用时快照停止，36小时过期健康失败，不能承诺始终24小时RPO或外部告警送达。
- 保留最近三个不同UTC日期的已验证备份；未知／损坏／发布前恢复点保留。只在本轮成功且服务器确认后执行保留策略。
- 排除：异地云服务、物理独立盘采购／分区、Mac远程登录／公网监听、删除服务器恢复点、服务端明文解密、恢复生产数据。
