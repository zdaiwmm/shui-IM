## 确认方案与范围

H5 遮蔽优先；页面遮蔽、会话有效性、系统操作分别管理。普通回焦不直接撤帘。明确归属的操作在真实可见且聚焦、原会话及期限有效、操作完成/取消且无后台信号时可恢复；无可靠结束信号的工具和无法归属的失焦须主动继续。隐藏、pagehide、freeze、显式锁定、空闲到期优先真正锁定。通行密钥网关维持既有认证例外。

不固定采用此前建议的普通失焦 60 秒。未归属失焦从现有短交接上限 2.5 秒作为实验起点；仅为待真机确认的候选，不作为已证可用性结论。明确选择器仍有 5 分钟上限，媒体权限仍有 30 秒上限，空闲仍为手机 10 分钟、桌面 30 分钟；所有到期均在返回/结算前主动复核，不依赖定时器是否及时运行。

普通遮蔽只控制呈现、可见已读与恢复；不回滚已持久化消息、草稿和待发记录。真正锁定沿用运行期清理及旧会话结果拒绝。系统分享/导出已明确交给系统的内容属于用户授权输出，H5 遮帘不控制系统分享界面自身的预览。

先做遮蔽与输入/选区兼容性实验、原生视频对照和切后台证据采集。无法遮蔽的原生视频若被实测确认，再针对该路径改内联；不凭静态假设提前改变视频策略。本次不增加额外点击；原生 API 在既有用户操作中同步预遮蔽后直接调用，不靠固定帧延迟维持用户激活。无法保证系统截图等待浏览器重绘，该边界留待真机验收。

## 可行性及改造规模

这是隐私生命周期的局部改造：新增 `src/lib/privacy-surface.ts` 管理有界呈现与恢复，接入原有 app 事件及工具 owner，调整遮帘样式与 dialog 的 inert 归属。真正锁定继续复用原运行期清理；消息协议、密码学、数据库和整套页面结构不重构。

机制证据：两引擎产品专项验证“覆盖后编辑焦点/选区仍在”和“失焦期间四角/中心始终命中不透明遮帘”；恢复须通过原会话、epoch、完成状态和绝对期限。浏览器会冻结任务，不能把 timeout 回调及时执行作为安全依据，因此返回与结果结算主动检查两个时钟，参见 [Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)。前台判断结合可见性与实际焦点，参见 [Document.hasFocus](https://developer.mozilla.org/en-US/docs/Web/API/Document/hasFocus)。工具归属不是浏览器提供的失焦原因认证；其可用性与系统缩略图效果仍必须以实体设备证据确认。
