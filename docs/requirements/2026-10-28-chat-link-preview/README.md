## 已确认需求范围

用户需要类似所提供 Telegram 截图的网页预览卡片，触发点在输入阶段。

1. 输入或粘贴完整网页网址后，短暂停顿自动获取信息，无需先发送消息。
2. 输入区显示网站名、标题及关闭按钮。关闭卡片保留链接文字；删除网址收起预览，更换网址更新预览。
3. 发送后的消息保留文字和可点击链接，并显示网站名、标题、摘要及可用配图；支持底部大图、右侧缩略图、无图文字卡片。
4. 获取失败不阻止发送。预览服务在消息发送前获得待预览网址，不接收其余聊天正文；发送出的卡片文字和图片随消息加密。
5. 点击卡片在新标签页打开网页，保留原聊天页。正文网页链接沿用同一打开方式。
6. 本轮先做原型和流程图。用户明确允许静态图，替代本轮默认的可交互原型；该例外不授予正式实施、合并或生产发布权限。

## 现状与实现约束

- 基线 `src/app.ts` 的 `createMessageElement()` 及 `clearMessageTextSelection()` 用 `textContent` 绘制消息；没有正文网页链接识别或卡片。
- `src/lib/types.ts` 的 `TextPayload` 与 `src/lib/message-payload.ts` 的严格白名单尚不支持链接卡片字段。正式实施需要定义加密卡片载荷、旧客户端协商及可用图片传输方式，不能只拼接 HTML。
- `server/index.mjs` 的 CSP 仅允许本站连接与本站／blob／data 图片；当前没有网页信息预览服务。正式实施不能通过开放任意远程脚本或直接嵌入网页来代替预览。
- `SECURITY.md` 定义聊天密文、服务端不接收明文消息与回复预览等现有边界。发送前网址抓取是本需求已讨论的数据边界；未来实施必须明确有限例外、网络隔离和日志策略，避免把“正文仍加密”误写为“预览服务看不到网址”。
- `desktop/macos/Chamber.swift` 当前将用户点击的外部 HTTP(S) 链接交给默认浏览器，同源新窗口另有原窗口加载规则。用户的新标签要求在浏览器／PWA与原生容器中都需要分别核实；本轮只展示静态目标。

## 最终产品方案 V1.1

### 输入与识别

输入或粘贴 HTTP(S) 网页链接，以及可补全为 HTTPS 的 `www.` 地址后，用户短暂停顿即自动识别，不需要点击发送或另外确认生成。一条消息默认生成一张卡片，选择文字顺序中的首个可预览网页链接。网址末尾的中文标点不纳入跳转地址；普通文字不被解释为 HTML。

输入区上方展示紧凑预览：网站名称、最多两行的标题和关闭按钮，不在编辑区展开完整摘要与大图。获取中显示简短状态，用户仍能继续输入、换行或发送。

### 草稿变化与关闭

- 继续输入普通文字，不重复获取相同网址；预览跟随当前草稿。
- 更换网址，取消旧请求并重新获取；删除全部可预览网址，立即收起预览。
- 点击关闭只移除本条草稿的卡片，保留链接文字；同一网址不因后续继续输入而自动弹回。替换成不同网址后重新识别。
- 获取结果必须匹配当前草稿、网址和打开状态；旧结果不能覆盖新预览。离开或隐私锁定清理临时内容。

### 发送后的卡片及图片规则

正文与网址保留在原消息气泡，下面附网页卡片，包含网站名称、标题、可用摘要和可用图片。摘要默认最多三行；图片保持比例并限制展示高度，不能为填满区域而放大模糊图。大图／缩略图的选择取决于网页给出的图片来源、用途和质量，而非按网站名称固定。

| 可用图片情况 | 展示形态 |
| --- | --- |
| 有清晰的文章内容封面、活动海报或视频封面，适合展开阅读 | 卡片底部大图 |
| 只有网站 Logo、账号头像，或图片分辨率不足以展开 | 卡片右侧缩略图 |
| 未提供图片，或图片校验／加载失败 | 纯文字卡片 |

同一网站可以出现不同形态。例如 X 帖子有清晰内容配图时也可显示大图，活动页面只有 Logo 时使用缩略图。判定依据采用网页提供的信息、图片来源与尺寸等可核实信号；不把无法可靠识别的图片用途当作事实。最低图片尺寸、比例和高度限制是实施参数，不在当前讨论中编造为已获确认的数值。

发送前确定并固定卡片内容与展示形态，双方展示同一份预览；不因接收端重新抓取、屏幕不同或原网页后来改变而自动切换布局。移动端和桌面沿用项目既有主题、字号、圆角与可访问操作尺寸。

### 发送与失败

- 预览已成功：将正文、卡片文字、选定形态及已验证配图作为同一条加密消息发送。
- 获取中、失败或已关闭：立即按原有发送流程发送文字和链接，不等待网页预览。
- 发送后到达的抓取结果，不补改已经发送的消息。
- 失败可重试或关闭；没有配图不等于整个预览失败，有可靠文字信息则显示文字卡片。
- 预览缺失、无效或旧客户端不支持时，保持正文可读、网页链接可点击；正式实施沿现有能力协商约束降级，不向旧客户端发送会导致整条文字消息被拒绝的载荷。

### 打开与既有消息操作

点击卡片任意有效区域或正文网页链接，均在新标签页打开，保留原聊天、草稿与阅读位置。显示的网址、网站来源和实际跳转目标必须核验一致；跳转不携带聊天内容。浏览器／PWA 的系统承载方式及 macOS 容器适配在正式实现中分层验收。

复制保留原始消息文字和网址；现有长按菜单、选择文字和滑动回复继续可用，避免与点击链接互相误触。已有历史文字消息可识别为可点击链接，但不自动把旧消息中的网址交给预览服务补抓卡片；新发送的卡片作为消息快照保留在历史中。这项历史边界是最终整理补充，防止将输入阶段的抓取授权扩展成遍历历史。

### 数据边界与本期范围

生成预览时，预览服务会在发送前读取待预览网址，即使消息最终未发送也可能已经抓取；其余聊天正文不交给该服务。图片经发送端校验后加密传输，接收端不直接加载外站图片或重新抓取网页。用户主动点击卡片后，才按正常网页访问处理。

本期只处理公开网页的链接识别、输入预览、发送卡片及跳转，不包含网页正文阅读器、自动播放视频、登录后页面抓取、历史消息批量补卡、卡片编辑器或手动切换大图／缩略图。站内邀请、设备加入、恢复链接、内网与本机地址不生成预览；普通查询参数也可能含敏感材料，不能承诺自动识别所有秘密。特定网站拒绝抓取时按文字链接降级，不承诺任意网站达到 Telegram 的同等预览结果。

### 实施前须落定的技术参数

卡片字段与旧客户端协商、网页／图片网络隔离、重定向及 DNS 核验、大小／超时／并发限额、缓存与日志保留、离线草稿和隐私清理仍需在正式实施时按安全契约核实。它们不改变以上产品行为；若发现必须改变已确认的数据边界或关键交互，再只对受影响部分重新确认。当前没有任何已实现或已验证这些能力的结论。
