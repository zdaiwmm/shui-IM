## 目标、现状与证据

- 用户要求：对方上线不要推送；在设置内自行填写通知文案，最好覆盖截图三行；页面解释修改影响位置；先出原型。
- `public/sw.js` 当前用固定标题 `Quiet Room` 和正文 `有一条新消息，解锁后查看。`，每次无内容唤醒均显示该通用提醒。
- `server/index.mjs` 的消息提交分支无条件唤醒，未过滤 `countUnread=false` 的已读、反应、撤回及相册专用同步；上线本身的 presence 广播没有推送调用。进入聊天会发已读事件，是用户所述误提醒的可能触发链，未做真机复现。
- 浏览器接入授权请求另有原有唤醒调用，不能在过滤聊天同步时误删。
- [Apple 的标准通知示例](https://developer.apple.com/videos/play/wwdc2022/10098/)使用 `showNotification(title, { body })`，没有任意替换来源的 subtitle 参数，通知仍归属于网站。结合当前接口，设计推断截图中的来源行由系统管理。截图三行映射仅为示意，实际系统可能显示应用名、调整顺序与截断；真实 iPhone/iOS27/Safari 尚未验证。

## v4 方案与边界

- 设置 → 本机 → 通知管理新增“通知文案”子页。标题／正文统一用于本浏览器或主屏幕应用、本机所有已开启提醒的空间，不同步对方、其他设备或其他浏览器。
- 第1行通知标题和第3行通知正文可编辑；第2行网站来源 `ai.shui.click` 只读，直接说明由系统显示。取消预览内的可点击编号与编辑图标；直接使用下方触屏输入区。
- 更改不重命名主屏幕图标，不修改聊天内容或已显示旧通知，不隐藏真实网站来源。系统额外显示的应用名、行序、换行与截断不可承诺一致。
- 实时预览为未保存草稿，点击保存才生效。标题上限24个用户感知字符，正文80个；空白使用默认值，超长或不可显示控制字符原位提示，输入保留；这些上限为本版待确认建议。只支持固定文字，不做动态变量，不自动插入私密内容。
- 总通知关闭时仍允许编辑和保存，之后重新开启生效。保存失败保留草稿与原保存值；保存中禁用重复保存、恢复默认、返回和编辑。恢复默认先更新草稿，保存后生效。
- 返回遇未保存修改时使用底部模态操作面板，允许继续编辑或放弃；背景不可操作。取消保存不等于更改旧文案。刷新时原型内存状态恢复默认；浏览器离开提示受系统控制。
- 页面说明自填文字可能显示在锁屏，不应填写隐私信息。正式实现建议在本机为 worker 持久保存必要非敏感文案，仍保持服务端无内容唤醒，不上传自填文字，不为后台通知解锁聊天保险库；具体持久化和生命周期将在实施前核实。
- 过滤目标：对方上线及在线状态、已读／反应／撤回／相册专用更新不产生新消息推送；真正新聊天消息沿用原有订阅与去重规则。保留浏览器接入授权请求的独立流程。本轮原型不提前改消息协议或服务端逻辑。
