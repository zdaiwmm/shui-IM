## 设计和验收约定

- 沿用 DESIGN.md、PRODUCT.md、docs/design/mobile-visual-standard.md、src/design-tokens.css 和 src/lib/language-feedback-ui.ts 的反馈字段、系统字体、圆角、44px 控件与项目主题。演示聚焦故障反馈局部，不复制整个聊天界面。正式版在已解锁的既有失败提示处提供入口，继续遵循隐私遮挡、锁定与清理；保留原有消息及附件重试语义。
- 两站独立存储。已落盘才显示已记录。故障编号全随机，不复用房间、消息、设备或任何协议标识。网络中断或无保存回执时标明未确认，允许用户复制本地阶段和原因码；重复上报同一事件须幂等，故障上报的重试不能重发业务操作。客户端观察与服务端证据分开，网络超时不能推断服务端写失败。
- 建议关键阶段覆盖进入聊天的本地会话、身份校验、历史读取，发送消息的加密、发件箱持久化、提交与回执，附件的本地读取、加密、上传与分片写入、完成确认。具体埋点以真实调用边界为准；可预期取消和正常离线排队不算业务失败。
- 仅收白名单字段以及随机编号、环境、服务器时间和前后端版本。限流、限量、最长保留 7 天，持久化应覆盖重启。运维只读查询并核验权限；禁止采集原始栈／异常文本、完整 URL、聊天内容、附件名和身份材料。不依赖第三方遥测。服务端持久化失败或磁盘满时不能给出已保存回执。
- 两环境分别验证三条业务路径，额外验证附件读取与服务端写分片两个不同故障、错环境查无记录、离线未上报、重报幂等、清理到期、重启仍可查、拒绝未授权查询和字段泄漏。模拟界面不构成这些生产、持久化或真机证据。

原型自查：桌面 Chromium 的 390px 深色和 1280px 浅色窗口均通过。每个尺寸分别模拟两环境的四个故障、反馈附号、按号查询、错站查无结果，以及离线未上报→恢复后同编号可查。未连接生产服务，未做物理设备验收。

## 实施与验收

源端按真实步骤分类，服务端有回执才显示已记录。客户端从已解锁失败提示进入现有表单，编号默认不附带。运维在对应主机执行只读按号查询，见 [OPERATIONS.md](../../../OPERATIONS.md#按用户反馈的故障编号查询)。版本 2026.11.03.3。初始候选 5b15bb54 的本地 1,276 项单元／集成与 92 个浏览器入口、PR CI 41611261585 均通过。主线 #492 占用原序号，已保留该版及发送修复并重新验证合并候选。

本地 Chromium 专项对两个独立应用进程分别注入读取本机设置、持久化文本待发箱、读取所选附件、服务端写分片失败。各环境从真实应用路径获得四个不同编号，重启服务进程后原库全部命中，对侧库全部未命中。浏览器上报离线后用原编号重试，反馈自选附号从前端提交到真实接口。上述本地专项使用合成环境与数据。公开接口限流、同源校验、到期清理、兼容旧反馈表和重复提交有专项回归。
