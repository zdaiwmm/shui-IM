- 新端默认选中旧端当前空间，无消息、预览、在线订阅或输入框；底部“申请对方授权”再次直接验证，成功后建立绑定该空间和独立新公钥的请求。
- 对方进入并解锁空间自动弹窗。关闭保留请求，空间列表同一行右侧按钮可重开。服务端创建后十分钟到期，对方弹窗关闭并移除按钮/提示；申请端可重新验证申请。拒绝、取消或撤销也阻止迟到批准。
- 对方签名批准且 MLS 加入实际完成后才开放聊天。每人每空间三设备上限、原设备可用、新设备无加入前历史等边界保留。
- 恢复继续采用单独总恢复码和双方确认流程，不把正常接入改称恢复。

## 实现与安全边界

- 既有通行密钥只解锁本地保险库。新增独立用途 PRF 输入及 HKDF 细分能力用于请求信箱、加密交付和本地外壳；原始 PRF 不发服务端、不写公开凭据记录。
- 身份链为：空间设备签名的申请根证书 → 旧端为特定新浏览器签名的申请委托 → 新浏览器签名的空间/公钥/请求/令牌摘要 → 空间对方的 MLS Add。委托仅允许申请，同方旧端不能使用普通 Add 绕过对方批准。
- 接入目录与 QR4 恢复目录隔离；不含恢复码、旧私钥、消息、预览、未读观察权限或 MLS 私有状态。存量空间解锁准备后更新独立加密目录，新端可按需刷新，不必重新认可浏览器。
- 请求服务端原子检查截止时间、状态、源设备撤销、对方角色、当前成员事件序号和设备上限；重复请求不续期。终态保留有限数量的摘要记录阻止重放，不保留整份请求正文。
- 新端验证公开成员链并消费自己的 MLS Welcome 后，一次保存 ready 保险库。待处理请求与独立私钥只在本地密封记录中保存；跨标签页原子比较后写入，锁定中止请求并清理界面。
- 详细协议与局限见 [SECURITY.md](../../../SECURITY.md)。无账户模型保持不变；网页不能发现未准备、未解锁或无法使用所选凭据的端点。
