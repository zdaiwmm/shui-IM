## 方案与边界

- 固定入口增加 `--cloud`，只触发 main 上手动生产工作流，绑定唯一请求；生产环境保留审核、仅 main、单写者和 OIDC 短凭据。没有 push 自动部署，不传本机 SSH 私钥。
- 临时 CI runner 复用完整镜像校验：精确应用 SHA 最新完整 CI、run／attempt、摘要、Docker 唯一标签及配置 ID。只在 CI 下载大文件，本机仅回读小回执。
- 服务器取得短期 GitHub 下载地址，使用有界 ZIP 元数据范围读取，单次打开镜像内容 HTTP 响应，再以有限缓冲流送原 root helper。服务器不保存 ZIP、gzip 副本或新构建缓存；Docker 导入及镜像层仍占用磁盘。原容量门禁、冷备份与每日保留继续有效，不执行 builder prune、不清理业务数据来放行。
- root helper 增加可选前版 SHA，持原锁比较线上状态并检查正向祖先，拒绝竞态或降级。必须从已审阅、通过 CI 的提交独立原子安装，普通发布不更新 helper。
- 传输错误、大小／摘要／CRC 错误在关闭镜像流前失败；外层不自动重发。命令状态不明、超时、回执缺失时先独立回读。云命令最长一小时，轮询结束不等于停止服务器任务。
- 下载短票据只存在临时命令／内存及云命令历史中，可能保留到平台历史过期；票据短期失效，不向服务器下发 GitHub 长期令牌，日志／回执禁止票据。现有管理员身份只调用既有 sudo 入口；RAM 命令权限需真实核验，不把旧 doctor 成功当发布权限已具备。
- 成功云回执仍需独立 `deploy:readback` 和第二工作树文档对账；真实 iPhone／Safari 验收不由发布成功替代。
