## 已确认方案与设计依据

用户反馈录音后播放不清晰，具体为「有杂音、破音或断续」；环境为「iPhone Safari，手机直接录放」。气泡希望与微信一致，解决现有过大的问题。

- 当前链路：`src/lib/voice-recorder.ts` 默认设备采集，优先可用 MP4，64kbps；解码后经 OfflineAudioContext 转为 24kHz 单声道，`voice-audio.ts` 写 16-bit WAV。`voice-player.ts` 使用 HTMLAudioElement 播放已完整校验文件。音频不经过服务端转码。
- 起始基线几何：`src/voice-messages.css:182` 不按时长区分，宽 `min(280px,100vw - 68px)`；44px 播放／seek 区、波形、内距和底部元数据共同占高。
- 设计依据：本基线 `PRODUCT.md` Voice Messages、`DESIGN.md`、移动视觉规范 11.1／11.4、`src/design-tokens.css`、实际样式加载顺序及既有录音／播放组件。场景是两人使用手机在日常环境快速收听，沿用现有系统字体与明暗主题。
- 已确认方向：微信式紧凑气泡；用户于原型交付后明确授权正式实施。采用现有产品的绿色浅色基础、受控绿色语音发送面与主题适配；不探索新品牌或整站视觉。跳过图像方向探针，因范围明确且为局部组件调整。

### 已确认 V1.1 的具体行为

1. 语音主体可视高40px，整条按钮高44px；小圆角与侧向尾角，发出与收到左右镜像。声波图标位于说话一侧并向气泡内展开，时长在气泡内紧邻图标内侧（8px），例如 `6″`；收到为图标在左、秒数在右，发出左右镜像。时长显示向上取整到整秒，原有0.5秒至5分钟范围不变。
2. 常规390px预览宽度为84–220px，1–60秒线性增长，60秒后封顶；320px时受可用宽度约束，不能溢出。发送／加载／失败不改变该条气泡宽度。
3. 时间与发送回执放在气泡下方，不再撑高着色主体。回执仅表达原发送／已读事实；不新增“已听”回执。原型均为合成状态，没有真实发送或已读。
4. 默认移除聊天气泡的完整波形与拖动进度条，整条点击播放、再点暂停，暂停后保留位置，再次播放从保留位置继续。结束后可重播，声波动画只在播放中出现。减少动态时用静态边界表示播放。
5. 保留单条加载／播放。点击另一条先暂停前一条；加载可取消；失败原位提示并重试；模拟发送失败重试不新增消息。长按／右键演示回复和删除，长按后的点击不会触发播放。锁定、隐藏或离开停止活动操作；返回不自动播放。
6. 引用在主体上方展示，因此带引用的消息总高可以增加；普通主体保持40px。录音阶段的波形、试听与裁剪保持既有产品设计。

正式实施同步更新PRODUCT.md、DESIGN.md、移动规范V1.24及真实组件回归。最初待审内容由原型提交`6fb273b669d1f9d4b3aa9a2c985f7756556a46b4`定位，确认后的产品结果与音质证据分开记录。

## 原型、流程和启动

- [交互原型](prototype/index.html)：V1.1，合成聊天列表与可操作状态；不播放真实聊天音频，不使用真实业务入口、Service Worker、邀请、保险库或恢复数据。
- [流程可视图](prototype/flow.html)／[Mermaid源码](flow.md)：V1，覆盖播放、暂停、切换、失败重试、长按和隐私停止；另含音频对照流程。HTML是同版可视摘要，源码保留完整分支。
- [本地音频对照](prototype/audio.html)：导入当前基线真实录音器和现有加解密函数，自动模式仅使用合成输入。可由用户另行主动点击4秒本机麦克风录音；本轮没有使用物理麦克风。指标去除设备ID，不持久保存录音。
- [验证结论](validation.md)：已证实结果、失败历史和真机缺口。
