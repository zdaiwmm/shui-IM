## 实现边界

1. CI 为 AMD64／ARM64 构建、验证并保存镜像归档和清单；产物绑定完整代码 SHA、CI run、attempt、架构、镜像 ID、长度及 SHA-256。只接受精确最新成功 main 完整 CI 的产物。只上传主线镜像，保留最近三个版本并设7天过期；过期需重跑同一精确提交的 CI，不改发其他版本。
2. 发布入口选择一个命名环境，配置独立保管；未知／错配环境不回落到旧目标。各环境独立管理域名、证书、密钥、数据、备份及版本，分别部署和回滚。第二套实际部署不在本批内。
3. 受信本机通过既有 SSH 流传输已核验归档，服务器校验传输摘要、镜像 ID、源提交和本机架构，替代服务器构建。继续使用维护门、冷备份、失败保护、独立回读和精确发布回执。
4. 自动保留跳过并报告脏目录、忽略文件、锁定／检查失败，继续处理其他合格目录；不强制删除或重置。存在保留异常时整体仍报告部分失败，不伪装全部成功。
5. 原监督维护计划绑定主机、当前版本、所有现有镜像和容器；维护窗口中停止原容器，检查内存后定向清理7天前缓存、保留2 GB缓存目标。实际仍导致失响应，**本机已禁用该方式**。超时不代表守护进程工作结束；本轮经新启动会话解决旧执行状态并恢复原容器，不原样重试。根目录事故标记阻止后续工具升级重新执行 plan／apply。

不删除业务数据、附件、恢复材料或受保护备份，不直接删除 Docker 层目录，不调整容量门禁，不新增自动生产发布。
