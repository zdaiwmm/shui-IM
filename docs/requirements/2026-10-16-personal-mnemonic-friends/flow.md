# 邀请密室 · V4.1 评审流程

状态：设计评审，正式实施暂停。[可视流程图](flow.html) · [原型](prototype/index.html) · [详细方案与待确认项](README.md)。内部动作不是额外用户页面；加密/服务端动作是拟定契约，未实现。

## 1. 快速创建与聊天内激活

```mermaid
flowchart TD
  A[首页：A点击创建密室] --> LOAD[加载动画：密钥创建中、匿名身份创建中、准备密室]
  LOAD --> LOCAL[内部：本机创建或复用身份，准备独立设备密钥]
  LOCAL --> AC[A待加入聊天：突出复制邀请链接]
  AC --> SHARE[通过原有可信渠道发给B]
  SHARE --> BL[B打开有效邀请：身份准备动画与阶段描述]
  BL --> BC[B直接进入待激活聊天：无历史、输入、通话或保险箱权限]
  BC --> GET[B点击系统消息中的获取验证码]
  GET --> REQ[创建绑定密室、身份、设备、邀请版本的本次请求]
  REQ --> CODE[A聊天临时显示本次4位码与申请编号]
  CODE --> TRUST[A与B原渠道核对联系人及同一申请，再告知本次码]
  TRUST --> INPUT[B在聊天卡片4格填写并激活]
  INPUT --> CHECK{本次绑定、码、时效、权限均有效？}
  CHECK -->|正确| ACTIVATE[原子确认成员，消耗邀请及验证码]
  ACTIVATE --> CHAT[双方进入可通信聊天]
  CHECK -->|错误且未超限| INPUT
  CHECK -->|超限、过期、旧码| DENY[保持待激活，可受限重新请求]
  REQ -->|A拒绝或B取消| DENY
  BC -->|链接失效或已使用| INVALID[明确失败，联系邀请人重发]
  DENY --> GET
  AC --> SETUP[后置四步保护]
  BC --> SETUP
  CHAT --> SETUP
```

打开/预览链接不申请、不占名额、不出码。4位码建议5分钟、5次错误，正式必须有跨请求累计限速和冷却。验证码不是会话密钥，也不能独立证明现实身份。创建/激活断网先查同一操作结果，不重复创建或加入；已有应用锁不能被邀请绕过。

## 2. 一次只引导一项保护

```mermaid
flowchart TD
  CHAT[聊天内低权重提示：当前一步与完成数] --> ONE[1 应用锁：通行密钥或本机密码]
  ONE --> RETURN1[完成后返回聊天，展示下一步]
  RETURN1 --> TWO[2 入口遮蔽层：开启或明确暂不开启]
  TWO --> RETURN2[返回聊天]
  RETURN2 --> THREE[3 自动锁定：离开、闲置1或5分钟、暂不]
  THREE --> RETURN3[返回聊天]
  RETURN3 --> FOUR[4 主动保存身份助记词]
  FOUR --> AUTH{本机已有应用锁？}
  AUTH -->|有| FRESH[原验证方式新鲜验证，取消不展示]
  AUTH -->|无，临时会话| SEED[本人本机查看12个编号词]
  FRESH --> SEED
  SEED --> SAVED[我已保存，返回聊天]
  SEED --> OPTIONAL[可选本机核对3词，不是服务端认证]
  OPTIONAL --> SAVED
  SEED -->|离开、锁定或展示到期| HIDE[清除展示与输入]
  CHAT --> LATER[稍后再设，继续当前主任务]
  LATER --> SETTINGS[设置中继续，已完成项目不重复]
```

顺序引导不阻塞邀请或激活后聊天，设置可按需进入任一项目。未配置应用锁前如何跨刷新保管身份仍待确认，不能把“稍后”冒充已保护。原型采用临时会话语义、模拟本机验证与60秒隐藏，不验证真实凭据/后台计时。聊天顶部为在线状态胶囊与设置，锁定在设置；不设底部导航、左上返回或整行标题栏。

## 3. 新设备、关闭与共同恢复

```mermaid
flowchart TD
  NEW[新设备恢复：本机输入本人12词] --> ID{格式、身份记录和目录完整性有效？}
  ID -->|否| BAD[本机显示错误，不自动注册新身份]
  ID -->|是| DIR[恢复本人未关闭密室目录]
  DIR --> DEVICE[生成全新独立设备密钥，请对方批准所选密室]
  DEVICE --> APPROVE{批准与MLS授权完成？}
  APPROVE -->|是| ENTER[进入旧密室，按有效备份恢复本人历史]
  APPROVE -->|拒绝、取消或过期| NODEVICE[无消息或历史权限]
  OPEN[已激活密室] --> CLOSE[任一原参与者主动关闭]
  CLOSE --> OWN[必要时先保管，再本机验证本人完整12词]
  OWN --> SERVER{服务端确认本次关闭？}
  SERVER -->|否或网络不确定| WAIT[显示尚未关闭，查同一次操作结果]
  SERVER -->|是| CLOSED[移除入口、停用会话、失效旧邀请及未完成申请]
  CLOSED --> KEEP[保留密文与身份，原保险箱权限不变]
  KEEP --> FRESHROOM[可用同一身份创建新密室，新密钥新邀请]
  KEEP --> ASK[主动证明本人身份，选择原密室并发起共同恢复]
  ASK --> LINK[给原另一方发送同一次恢复邀请]
  LINK --> PEER[对方在自己的设备验证自己的12词并确认]
  PEER --> BOTH{双方证明、关闭版本、目标设备、时效均一致？}
  BOTH -->|拒绝、撤回、过期或不符| STAY[保持关闭，不复用旧证明]
  BOTH -->|有效| KEYS[完成所需设备授权与会话密钥状态]
  KEYS --> RESTORED[原密室入口恢复]
  RESTORED --> HISTORY{有可用本机历史或有效加密备份？}
  HISTORY -->|有| PAST[恢复本人有权限且备份覆盖的历史]
  HISTORY -->|无| EMPTY[明确旧历史不可恢复，可以开始新聊天]
```

共同恢复建议15分钟。两份助记词不交给同一人或设备；证明绑定同一请求，不能仅用两个客户端布尔值授权。在线端收到关闭后立即移除，离线设备须下次联网核验；截图/已有副本不能收回。共同恢复的产品门禁与抗服务端失陷的密码学双人控制是不同承诺，后者待专项设计确认。

## 4. 旧空间逐个迁移

```mermaid
flowchart LR
  OLD[原设备解锁或完成旧恢复授权] --> ROLE[核验本人原角色与权限]
  ROLE --> BIND[逐空间绑定本人个人身份]
  BIND --> WAIT[另一方在其设备绑定，等待期间旧空间可用]
  WAIT --> CHECK[核验原双方、角色与新绑定]
  CHECK --> KEEP[保留每个原密室和历史，不合并，不扩大保险箱权限]
  KEEP --> FORMAT[验证新目录与历史备份格式的回读]
  FORMAT --> LEGACY[按已确认兼容策略停止旧包写入或停用旧能力]
```

已有多空间架构保留，空间列表在设置；额外创建入口隐藏。旧QR3/QR4密文包可能含设备私钥，不能直接纳入新“不上传任何私钥”承诺。兼容窗口与已有包处理仍待确认，不能先清除旧材料再假报迁移成功。

## 5. 本机与服务端的数据边界

```mermaid
flowchart LR
  WORDS[本人设备：安全随机12词与种子] --> KEYS[本机按用途派生身份签名与解包私钥]
  KEYS --> SIGN[本机签名绑定用途、密室、设备、挑战、版本和时效]
  SIGN --> PUBLIC[发送必要公钥、签名与公开参数]
  PUBLIC --> VERIFY[服务端核验权限、防重放和状态版本]
  DEVICE[本机随机独立设备密钥与MLS私有状态] --> E2E[本机端到端加密与棘轮演进]
  E2E --> CIPHER[服务端仅协议密文与必要元数据]
  HISTORY[本机有效历史副本] --> BACKUP[独立加密历史与数据密钥封套，不含任何私钥]
  BACKUP --> CIPHER
```

助记词、种子、个人/设备私钥不作为明文、密文备份、哈希口令、URL、日志或统计事件上传。允许加密历史数据的密钥封套不等于允许上传身份私钥。现有恢复包包含加密设备私钥，是必须改造的差异；本图只描述目标。恶意脚本/扩展或已被控制的解锁终端不能由本图保证不泄漏。
