# 一键创建、聊天内激活与后置保护 · V4

状态：需求方向已确认，原型设计待确认；仅设计材料。对应[可视流程图](flow.html)和[交互原型](prototype/index.html)。“内部动作”节点不代表用户页面。

## A一键创建，B打开邀请直达聊天

```mermaid
flowchart TD
  A[首页：点击创建密室] --> AL[正在创建密室：短暂loading]
  AL --> AI[内部动作：本机自动生成12词并建立个人身份]
  AI --> AC[A直接进入待加入聊天页]
  AC --> L[复制邀请，原渠道发给B]
  L --> BL[B打开邀请：身份准备loading]
  BL --> BI[内部动作：自动创建本人身份；已有可用身份则复用]
  BI --> BC[B直接进入待激活聊天页，无历史和消息输入权限]
  BC --> GET[系统消息：需要验证码才能激活密室]
  GET --> CLICK[B点击获取验证码]
  CLICK --> REQ[提交绑定B身份与设备的本次请求]
  REQ --> CODE[A聊天内系统卡片显示本次4位验证码]
  CODE --> T[A通过原有可信渠道确认B，另行告知验证码]
  T --> F[B在聊天系统卡片内用4格输入]
  F --> V{身份、设备、请求、验证码均有效？}
  V -->|是| CHAT[双方密室激活，开放消息和通话]
  V -->|错误| RETRY[提示核对，达到上限则重新请求]
  REQ -->|拒绝、撤回或超时| NO[保持未激活，不授予会话权限]
  NO --> CLICK
  CHAT --> DEAD[本次验证码及旧邀请失效]
  AC --> SAFE[聊天内后置保护引导]
  BC --> SAFE
  CHAT --> SAFE
```

- 创建不展示助记词，不选择身份来源、不导入钱包助记词、不填昵称、不核对词、不先设置应用锁。只显示创建中，完成即进入聊天。
- B打开有效邀请后自动准备身份并进入聊天外壳。身份已准备好，不等于密室已激活；激活前不请求或展示旧消息，不开放消息/通话权限。
- 打开链接或链接预览不占用参与者名额、不出验证码。只有B显式点击“获取验证码”才提交请求，A才显示本次码。
- B始终停留在聊天内，4格输入和“激活密室”均在系统卡片中，不再跳独立验证码页。
- 4位码绑定密室、双方身份、B设备、单次请求和时效；建议5分钟、最多5次错误。正式实现必须跨请求累计限速/冷却，不允许更换请求无限猜测。
- A的验证码卡片不发给B、不写入聊天历史/备份/通知。A仍需通过原有渠道判断现实联系人，验证码不能独立证明现实身份。
- 已有可用本机身份不得被重新生成覆盖；已有应用锁不得因打开邀请被绕过。创建失败/重试复用已有本机身份和同一创建意图，不重复分配密室。

## 先使用，再配置四项保护

```mermaid
flowchart TD
  CHAT[已进入聊天页面] --> GUIDE[系统卡片：四项设置，可稍后]
  GUIDE --> LOCK[应用锁：通行密钥或本机密码]
  GUIDE --> COVER[入口遮蔽层：锁定时显示中性入口]
  GUIDE --> AUTO[自动锁定：离开页面、闲置1分钟或5分钟]
  GUIDE --> SEED[保存本产品生成的身份助记词]
  SEED --> SAVE[本人按顺序保存12词并确认]
  SEED --> OPTIONAL[可选：本机随机核对3词]
  GUIDE --> LATER[稍后再设，继续邀请、获取验证码或聊天]
  CHAT --> SETTINGS[右上设置：四项配置及空间列表]
  LOCK --> DAILY[下次解锁后直接回聊天]
```

- 后置卡片分别显示未完成项及进度。主流程不等待它；“稍后再设”仅隐藏本次提示，设置内始终可继续。
- 未配置应用锁的本机身份按临时会话设计。离开前提醒设置应用锁或保存助记词；配置应用锁后才加密持久化必要本机材料。这是V4待审安全设计，原型全为内存模拟，刷新总会重置。
- 自动锁定需要已有应用锁；暂不自动锁定也可作为明确配置。原型仅模拟配置与外部触发，不能作为后台、系统计时或真机验证。
- 助记词只在本人显式选择保存时展示。默认“我已保存”直接确认；3词核对改为后置可选的本机检查，失败不影响聊天，不是服务器认证。
- 助记词和根私钥不上传、不进入云端恢复包，不存助记词哈希作为口令；服务器使用公钥核验绑定请求的签名，保存必要密文/元数据。真实派生与签名尚未实现。
- 主页保留“恢复密室”，只恢复此前由本产品生成的身份。未知身份/无有效记录不通过导入任意钱包词自动注册身份或新建密室。
- 聊天顶部只有两个44px挂件按钮，背景连续，无整行标题栏、左上返回或底部导航；次级页返回在底部。空间列表保留在设置内，保留多空间架构但隐藏额外创建入口。

## 新设备与关闭后的共同恢复

```mermaid
flowchart TD
  NEW[新设备：首页恢复密室] --> OWN[本机输入本人已有12词，验证记录]
  OWN --> DIR[恢复个人身份和未关闭的密室目录]
  DIR --> DEV[选择旧密室，请对方批准本次设备]
  DEV --> OK{对应参与者批准且授权完成？}
  OK -->|是| ENTER[进入该密室，恢复本人有效备份]
  OK -->|拒绝、取消、过期| DENY[无历史和消息权限，可重新请求]
  OPEN[已激活密室] --> CLOSE[任意一方选择关闭]
  CLOSE --> BACKUP{本人是否已保管助记词？}
  BACKUP -->|尚未确认| FIRST[先引导查看和保存本人助记词]
  FIRST --> PROOF[在本机验证本人完整12词]
  BACKUP -->|已确认| PROOF
  PROOF --> CLOSED[双方入口移除，停用消息通话和旧邀请]
  CLOSED --> KEEP[保留服务端加密数据、个人身份和原保险箱权限]
  KEEP --> FRESH[可用同一身份创建新密室]
  KEEP --> ASK[一方主动验证本人助记词并发起共同恢复]
  ASK --> SEND[通过原渠道发本次恢复邀请给原参与者]
  SEND --> SECOND[另一方在自己的设备验证自己的助记词]
  SECOND --> BOTH{双方确认同一有效请求？}
  BOTH -->|是| RESTORED[原密室重新出现在双方入口，恢复有权限的历史]
  BOTH -->|否| STAY[保持关闭，旧证明不能复用]
```

- 关闭是可共同恢复状态，不是永久销毁；单方导入身份、日常解锁或恢复历史都不能绕过共同恢复。
- 双方各自验证自己的助记词，不交给对方或同一设备。共同恢复建议15分钟有效，拒绝/撤回/超时保持关闭，重新发起需重新验证。
- 关闭时旧邀请、验证码及未完成加入/设备任务失效。创建新密室使用新会话密钥/邀请，不复活旧邀请。
- 原保险箱只对原创建者开放，关闭保留其加密数据，不增加新共享权限。不承诺擦除截图、导出或离线副本。

## 旧空间迁移

```mermaid
flowchart LR
  OLD[原设备解锁，或走原恢复流程] --> CHECK[核对本人原有参与权限]
  CHECK --> BIND[逐空间绑定当前个人身份]
  BIND --> WAIT[另一方在其设备完成绑定]
  WAIT --> VALID[核验双方绑定与原角色]
  VALID --> ROOM[原密室、历史和保险箱权限分别保留]
```

旧空间等待绑定时仍可用，多空间不合并历史。QR3/QR4兼容仍需原流程取得原权限，不因新身份或聊天外壳可见而自动授予权限。
