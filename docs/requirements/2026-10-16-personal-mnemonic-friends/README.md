## 当前确认方向

产品面向已有信任关系的两个人，提供极私密的邀请聊天，不做公开资料、公钥搜索、好友申请/列表或钱包支付。个人身份负责连续性和恢复，用户首次无需理解私钥/助记词、填写个人资料或设置应用锁。

### 创建与受邀进入

1. 首页保留创建/恢复密室。新用户点创建，显示“正在创建密室”，在本机自动生成12词与个人身份，进入待加入聊天，立即可复制邀请。没有身份来源半屏、钱包助记词激活、保存/核对词或解锁设置前置页。
2. B打开有效邀请，先显示进入/身份准备loading，自动创建本人身份（已有可用身份则复用），随后直接进入待激活聊天外壳，不再有落地身份表单或进入确认按钮。
3. B聊天内系统消息提示“密室尚未激活”，提供“获取验证码”。打开链接本身不向A出码、不占用第二位参与者名额、不授予会话权限。
4. B点击获取后提交绑定自身身份、设备、目标及单次请求的申请，A聊天页临时显示4位码。A通过双方原有可信渠道确认B，另行告知代码。
5. B在同一聊天系统卡片用4格填写，点击“激活密室”。验证成功后双方才能收发消息、通话；激活前没有历史、消息输入或保险箱权限。拒绝/取消/超时/错误码均不开放权限。
6. 4位码建议5分钟有效、最多5次错误，必须单次绑定请求并排除历史/备份/通知。正式实现要跨请求累计限速和冷却，不能重建请求无限猜测。验证码不独立证明现实身份，原渠道联系人判断仍必要。

### 四项保护后置

聊天系统卡片引导应用锁、入口遮蔽层、自动锁定、保存身份助记词，显示未完成项与0/4进度。可以稍后再设，设置中始终保留四项入口；不阻塞复制邀请、获取验证码或激活后聊天。

- 应用锁：在聊天后选择通行密钥或本机密码，必要本机身份/聊天材料才加密持久化。尚未设置时按临时会话设计，卡片提醒离开前设置应用锁或保存助记词。真实持久化、首次目录写入和中断恢复仍需安全方案冻结，原型不承诺自动备份。
- 入口遮蔽层：锁定时显示中性入口，无联系人、密室存在、未读或历史预览；它不代替身份认证，不能保证外层浏览器/WebView/系统不留痕。
- 自动锁定：需已配置应用锁，可选择离开页面、闲置1分钟/5分钟、暂不自动锁定。原型只演示配置与外部模拟触发，不实现/验证真实后台计时策略。
- 保存助记词：由本产品在本机自动生成英文12词，用户显式保存时才展示。“我已保存”直接确认，随机核对3词后置为可选，完全在本机比较，不是服务器身份认证，不证明全部12词已可靠备份。

不再提供用任意已有/钱包助记词创建或激活身份的入口。“恢复密室”只用于本产品此前生成的身份，完整12词需核对词表/校验和及有效身份记录，未知记录不自动注册。助记词和根私钥不上传，不包含在云端恢复包，不存助记词哈希当口令；服务器用公钥核验绑定请求的签名，并保存必要密文/元数据。[BIP39](https://github.com/bitcoin/bips/blob/master/bip-0039.mediawiki)定义词与校验和，三词抽查只是产品交互建议。

### 已有边界继续保留

- 聊天主页，顶部仅两个44px挂件按钮（应用锁未配置时先到配置），背景连续，无整行标题栏、左上返回或底部导航；次级页返回在底部。
- 设置内保留空间列表便于测试，保留多空间架构/数据/创建逻辑，本期仅隐藏额外创建入口，未来付费权限另做。
- 新设备恢复个人身份及未关闭目录后，进入旧密室仍需对方批准当前设备。历史恢复不绕过批准，关闭密室不自动出现。
- 任一参与者验证本人完整12词后关闭已激活密室，双方入口同时移除、停止通信，服务端加密数据保留。未确认保存时先引导本人保存，再验证，不把这道门槛移回首次创建。
- 关闭后个人身份存在，可以创建新密室；重开旧密室须双方分别在各自设备验证本人助记词、确认同一有效恢复请求。建议15分钟有效，拒绝/撤回/过期保持关闭，旧证明不能复用。
- 原保险箱保持创建者权限，关闭保留数据，共同恢复不扩大权限。不承诺清除已有截图、导出和离线副本。
- 旧空间在原设备逐个解锁、双方分别绑定个人身份，保留每个原密室/历史/角色，不合并。等待时旧空间可用；QR3/QR4兼容保留原恢复授权。
