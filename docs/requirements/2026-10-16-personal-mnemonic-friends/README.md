## 目标与范围

用户明确将以空间恢复码为单位的主模型调整为个人助记词身份。每个身份拥有固定公钥，可以通过完整公钥找到已注册身份并加好友；双方接受后存在端到端加密的双人会话。本期不做钱包接入、资产、充值、支付、群聊或公开用户推荐。

现有 QR4 是本机集合恢复入口，内部依然有各空间的参与者、独立设备、QR3 归档和 MLS 状态。现状依据为根 PRODUCT、SECURITY、RECOVERY_BACKUPS 与 src/lib 中 spaces、crypto、mls、joint-recovery 模块。新模型需要新增个人身份与设备归属证明、好友申请、唯一会话及个人加密目录；不是恢复材料的纯文案改名。

### 已确认行为

1. 好友申请双方确认后建立会话，每对好友只有一条当前双人会话。
2. 在新设备导入个人助记词可恢复本人好友、会话目录；进入旧会话仍需对应好友批准该设备。不能凭助记词或目录读取成功自动开放消息收发。
3. 支持旧空间迁移，在具有原参与者权限的设备上分别绑定各自个人身份。
4. 本期保留原有保险箱权限，不变成双方共享或人人新增的私人保险箱。

### V1 设计建议，待第二次确认

- 默认生成 24 词标准助记词；具体导入长度、标准附加口令及派生版本在实施前冻结，不能自创兼容格式。原型仅用无效演示词，不产生有效秘密。
- 助记词派生固定个人身份与用途隔离的目录恢复能力；日常仍用本机通行密钥或密码。设备随机密钥与 MLS 状态保持独立，不从助记词静态派生所有消息密钥。
- 搜索只接受完整公钥；输入本人、公钥格式不全、未注册分别反馈。返回资料必须匹配输入公钥与签名，不能只信服务器提供的身份标签。
- 好友申请包含发送、等待、接受、拒绝、撤回与重试；重复、交叉请求不重复创建会话。受限请求、真实性校验及原子唯一性属于正式实现的验收范围。
- 个人好友及会话目录加密保存。新设备恢复先核验目录并设置本机保护，再持久化等待任务；逐好友批准，拒绝、取消、过期均不授予权限。尚未完成协议成员变更不能显示已接入。
- 显式恢复本人有效历史备份可独立于新设备批准；不授予新消息或通话权限。未备份消息、丢失的服务器原件和不存在的恢复目录不保证可找回。
- 同一好友的多个旧空间保留为独立历史档案，新消息进入唯一好友会话，不自动拼接旧历史或扩大原角色及保险箱权限。双方尚未完成绑定时继续旧空间行为；原型的“已迁移”仅模拟双方绑定验证。
- 现有 QR3/QR4 保留恢复兼容。仅有旧码时先走旧恢复流程取得原参与者权限，再绑定个人身份；不能只改 roomId、角色或公钥字段完成迁移。
- 个人身份可关联多个会话。服务端为搜索、申请及路由处理公开身份与必要连接元数据，不能承诺隐藏好友图谱或零元数据。

### 实施前必须明确的边界

- 多旧空间的切换时点、消息停止/转向规则、旧客户端兼容、失败回滚和审计映射；旧历史来源及权限保持可验证。
- 双方都失去设备时如何分别证明根身份并完成同一重建批准；原设备撤销/保留选择；不能把原有双确认恢复简单改成单方接管。
- 新好友会话中保险箱角色分配沿用现有创建者/参与者规则的具体映射；不得因增加好友模型自动开放对方权限。
- 助记词泄露后的身份更换、设备撤销、目录版本冲突和服务器回滚检测；固定公钥变化需重新核验，不能静默替换。

上述技术与异常边界将在正式方案中具体化。原型不对其密码学可行性、真实设备或生产状态作验证结论。
