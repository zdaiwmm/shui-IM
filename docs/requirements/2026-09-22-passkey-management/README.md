## 问题与目标

新浏览器需要用户在系统通行密钥选择器选择已有凭据，但现有用户名为 `vault-随机 UUID`、显示名称统一为“Quiet Room 本机保险库”，用户无法区分。页面也容易让已有用户再次创建新密钥。

目标：一套空间优先复用已有通行密钥；首次创建时使用清晰名称；设置中管理当前绑定密钥的名称。系统选择器中的标签需要真正更新，不能仅改变应用内备注。

### 已核实事实

- `src/app.ts:createPrivateSpace` 已在已解锁访问中复用当前密钥；每个空间内部加密与成员身份仍独立，不等于每个空间需要一把用户管理的通行密钥。
- 浏览器不能静默读取其他浏览器的数据，也不能可靠识别同一物理设备。现有接入以同一凭据派生的信箱中转请求，旧端批准后交付加密目录读取能力，再由空间对方批准聊天权限。
- 独立真机实验：iPhone16,1 / iOS 27.2 / Safari 27.2，用户按说明保存测试凭据并确认系统名称“已变”。接口存在；认证返回 userHandle 与创建时 user.id 一致；改名前后 credentialId、userHandle 和 PRF 结果相同。未测试生产旧凭据，未读取真实空间。密钥提供方未由程序独立证明。
- 系统名称可由 `signalCurrentUserDetails` 更新，但网页不能读取密码管理器的当前名称，也没有名称更新成功的可靠回读。应用显示自己保存的名称记录，不能宣称自动获得系统中手动改动的最新名称。

## 本次方案

### 1. 复用与命名

- 同一套空间从已解锁空间继续创建时复用当前通行密钥，不新增验证和命名步骤。
- 欢迎页第一项保持“创建私密空间”，使用蓝色主按钮；第二项为“接入本设备现存私密空间”，使用次级按钮；恢复入口保留。D2 按用户指定文案执行，“本设备”不改变跨浏览器发现仍需共享凭据和原端批准的能力边界。
- 真正需要新建密钥的首次创建、旧保险库首次绑定、恢复后重新绑定，复用同一名称输入组件，不额外加独立命名页面。首次创建在系统密钥创建成功后自动创建空间，成功即显示既有邀请半屏；不再显示单独“加入空间”页面、二次创建确认或新浏览器接入授权页。已接受他人邀请的原有加入业务是另一条流程，保持原契约，本轮不新增加入页面。
- 默认示例为“Quiet Room · 09月22日 · 01”，用户可编辑；用简短生成日期／序号等非敏感区分信息减少多个独立凭据都同名的情况。日期／序号只辅助辨认，不保证全设备唯一。不得从聊天内容、对方名称或设备指纹生成名称。
- 去除首尾空白，长度 1–40 个用户感知字符，不接受空白或控制字符；无变化不发更新。同名仅显示标签相同，不合并凭据。界面不声称通过名称认证身份。
- 首次创建将可读名称同时用于 user.name 与 user.displayName，并保存 user.id 和应用名称元数据。名称是系统选择器可见的标签，输入页不使用聊天机密作为示例。

### 2. 设置中的通行密钥管理

- 设置“本机”组新增入口“通行密钥管理”，入口不展示密钥名称。
- 每次点击设置入口，都在该点击的同步激活内直接唤起系统通行密钥验证；保留设置作为底页，不进入单独验证页面、不要求再次点击。成功后才进入管理页；取消或失败留在设置，入口下提示重试，不展示名称。
- 验证成功后展示应用记录的名称、当前使用标记、用途与复用说明、修改名称按钮。
- 点击“修改名称”直接在管理页上打开输入弹窗，同一点击内同步聚焦输入框并选中现有名称，唤起系统键盘；不导航到新页面。弹窗在键盘可视视口内布局，取消关闭弹窗且保持原名。保存、失败、输入校验、部分完成均在原弹窗内处理。进入验证与保存验证是两个独立步骤，管理页已打开不免除保存时再次验证。
- 保存再次验证指定当前 credentialId；验证取消、失败、超时、锁定或离开页面均不提交名称变更，迟到结果不能落入另一次操作。
- 改名只更新标签，不创建／替换密钥，不改变 user.id、credentialId、PRF 输入、空间身份、加密材料或历史访问边界。
- 名称关联通行密钥而非某个空间；同一浏览器内共享该凭据的空间统一读取名称元数据。密码管理器可以同步标签，但不承诺其他浏览器内的应用记录自动即时同步，也不承诺同步范围仅限当前设备。
- 旧凭据没有应用名称记录时显示“尚未设置名称”。通过认证回取 userHandle 并核对所选凭据后在原凭据上设置名称。不得猜测系统原名或把 credentialId 误作 user.id；未取回标识时阻止改名。

### 3. 能力与失败边界

- 正式开放前必须完成目标浏览器＋凭据提供方的真机验收。接口存在仅是必要条件，不能声称已经证明所有提供方可用。
- 已知不支持的环境在进入管理后提前显示不可编辑状态，不让用户先填写再降级为本地备注。
- 支持环境：再次认证 → 提交系统名称更新 → 保存应用名称记录。成功反馈“名称已保存／已通知系统更新显示名称”，不声称已回读所有系统或跨设备同步成功。
- 明确失败且尚未提交系统更新时保留旧名称、保留草稿供重试。系统更新已提交但本地保存失败时进入“结果待确认”，不声称原系统名称未变或已回滚；再次认证后幂等重试同一名称。
- 系统密码管理器中的手工改名不会通过 WebAuthn 自动回传；管理页提示“此处显示应用保存的名称”。

### 4. 新浏览器接入指引

- 使用已有通行密钥直接唤起系统选择器，选择器由浏览器提供，本轮不重画系统界面。
- 验证后等原端在线、解锁并批准，页面显示六位码、剩余时间、重新选择通行密钥与取消接入。
- 重新选择先终止旧请求并隔离迟到批准，再重新验证，不能让两次请求共用状态。
- 请求到期、无响应不等于没有空间；不可断言选错密钥。提示同时覆盖离线、未解锁和选错凭据的可能性。
- 原端核对码后只批准空间目录交付；空间对方授权与独立加入完成后才开放聊天，新端不取得加入前历史。

## 排除项

不做通行密钥删除、解绑、替换、自动合并；不枚举整台设备的密钥；不做扫码配对；不开放旧端离线时仅凭密钥取得目录；不调整恢复、清除本地数据、空间三设备上限及两层授权协议。本次修改正式客户端与配套测试文档，不更改服务端协议或生产配置，不发布。
