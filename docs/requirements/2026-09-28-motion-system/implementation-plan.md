# shui-IM 全站交互与动效优化完整方案

版本：V2 · 2026-09-28。本文汇总已沟通的完整实施范围，供最终设计与工程验收使用；方案形成不等于正式代码已经实施或原型效果已获确认。

## 1. 目标与交付方式

将 shui-IM 当前部分简单、僵硬的过渡，优化为响应及时、速度变化自然、手势有阻力、状态反馈明确、连续操作不中断的完整交互体验。消息发送只是其中一个场景。

现有十组原型是代表性样本，不是改动范围上限。取消第一批、第二批的分批交付安排：全站统一盘点、补齐设计、一次性实施、统一回归后完整交付。工程可以按依赖顺序开发和分段提交，但不得把未完成模块当作下一批遗留。

沿用现有视觉、排版、色彩与功能结构，不进行全站视觉重设计。参考 Telegram、微信、iMessage 的反馈清晰度与连续性，不声称复刻其实现或测得其曲线。用户提供的 Telegram 视频此前未成功播放，不能作为逐帧测量依据。

## 2. 体验标准

1. **即时响应**：按钮按下、拖动、取消先给出可见反馈，不等待网络或退场动画；业务成功只在真实成功后显示。
2. **分场景变速**：明确启动、加减速、停靠。小控件短促，页面和面板有重量感；阻尼感不等于所有元素回弹或统一放慢。
3. **跟手与收尾分离**：手势跟随当前位置；接近边界逐渐增加阻力；松手后根据位移、方向和速度完成或回位。
4. **可中断接续**：快速连点、反向、关闭途中重开，从当前视觉状态接续；手势保留有效速度，不跳回固定起点。
5. **主次协同**：主元素位移、邻近布局变化、遮罩和状态提示协调发生，不互相等待，不使用大量装饰性错峰。
6. **状态真实**：清楚区分按下、处理中、完成、失败、取消、不可用；动画不改变持久化、已读、权限、播放时间和恢复结果。
7. **安全与可访问性优先**：减少动态效果时直接或短淡入达到正确状态；锁定、隐藏、清理立即执行。

现有实现已使用多种非线性缓动，问题不能简单归因于全部使用线性速度。此次同时处理动画被重置、固定计时清理、几何突变、反馈缺失及多个动画争用同一元素等因素。

## 3. 完整覆盖矩阵

每行都覆盖入口、正常操作、取消、中断、失败或不可用等适用状态。复用组件须追踪全部调用方，不能只验证原型中的一个示例。下表是实施与检查范围；已符合目标的交互可保留，但必须记录理由及验证结果。

| 编号与范围 | 优化行为 | 核心验收 |

| M21 主题、尺寸与生命周期 | 检查浅深色切换、窄屏、横竖屏、视口变化和后台恢复；统一动画失效与恢复策略。 | 无闪白、溢出、过期动画补播；后台恢复直接对应有效状态；减少动态效果切换时也能收敛与清理。 |
| M22 状态栏、页面背景与底部安全区域 | 顶部由当前页面实际表面颜色协调 root、body、安全区域与可用浏览器主题提示；底部检查多余不透明背景、内容延伸和触达空间。 | 浅深色、不同页面与滚动位置不出现明显断色；最后一项可见可点；不承诺原生 Safari 工具栏透明，不以破坏聊天键盘／滚动稳定性换取透明效果。 |

## 4. 动效参数与实现方式

以下是实施调校的起始区间，不是已测得的最佳参数，也不是所有场景的固定播放时长。最终以正常速度交互、连续操作和目标设备验证确定。

| 动作类型 | 起始建议 | 约束 |
| --- | --- | --- |
| 按下反馈 | 下一可渲染帧开始；视觉变化约 60–100ms | 不延迟实际操作；立即松手也有合理反馈。 |
| 松手恢复、选中反馈 | 120–200ms | 柔和收敛，小幅度，无反复振荡。 |
| 局部状态、提示、回复栏 | 160–240ms | 简洁，避免文字长期模糊或透明。 |
| 消息与邻近布局 | 220–320ms | 及时进入、末段减速；按位移调节，不拖慢连续发送。 |
| 页面、抽屉、弹窗 | 260–380ms | 主体与遮罩协调；反向操作按剩余路程收敛。 |
| 图片展开、缩放与回位 | 240–380ms | 结合距离和手势速度；详情面板优先去除过长拖尾。 |
| 手势跟随 | 不套固定时长过渡 | 跟手阶段做位置／阻力映射，松手才进入收敛模型。 |

简单状态变化使用 CSS 或 Web Animations API 的非线性缓动；需要保留速度、重定向和边界阻力的手势使用轻量状态控制。默认不新增动画框架，不把全站强行切成同一种弹簧。

统一管理时长、缓动、阻尼和减少动态效果策略；每个元素的同一运动属性只有一个控制者。布局与手势需要同时运动时分离承载层，避免 transform 相互覆盖。中断前读取或保留当前位置，速度型交互保存有效速度；反向不先强制完成旧动画。

消息重排只测量和处理需要变化的可见元素，集中读取几何信息后集中写入。优先 transform／opacity；确需高度布局变化时局部处理，禁止逐帧扫描全部消息。不要对全屏模糊、大型媒体、长列表滥用持续动画或永久 will-change。

动画清理以完成／取消事件或控制器状态为准，保留异常超时兜底；不以硬编码时间作为唯一真相。所有异步回调校验操作身份与生命周期，关闭、离开、锁定、清理后可立即失效。DOM 销毁、焦点恢复、滚动锁与任务完成分别处理，避免视觉完成被当作业务完成。

## 5. 页面与代码覆盖落实

实施前基于当时核验的 main 建立“页面／组件 → 调用入口 → 操作 → 状态 → 实现位置 → 验证结果”的检查表，记录在本需求目录，不另外建立平行的完成记录。每项结果只能为：已优化并验证、现状保留并验证、系统控制且已验证网页衔接、受阻待验证。受阻项不能算完整验收通过。

主要落点包括：

- 共享动效 token 与控制工具、`src/app.ts`、基础样式、聊天布局及消息交互。
- 回复手势、聊天视口与键盘协调、隐藏手势、菜单与回应。
- 公共 dialog、空间抽屉、表情面板、保险库／相册／文件／收藏样式。
- 图片查看器及手势、详情面板、附件准备与上传展示、文档阅读器。
- 语音手势／录制／播放展示、通话展示及对应样式。
- 设备、设置、备份、恢复、引导、通知、系统颜色与安全区域。
- 对应测试与需求记录；只有正式行为契约发生已确认变化时才更新产品契约。

以实际加载链和调用图决定修改文件，不把这份目录当成每个文件必须重写的清单。服务端、数据库、协议、加密、密钥与通话信令不因动效需求而改动。

## 6. 状态栏与浏览器底部的具体边界

顶部：按页面表面统一颜色来源，处理浅深色、普通子页、覆盖层和主题切换；浏览器主题提示仅使用目标环境支持的能力，不能把网页控制当作系统状态栏的完整控制权。

底部：检查是网页自身不透明底层、安全区占位还是浏览器原生材质。网页层可去除无必要的遮挡并正确延伸内容；保留底部按钮触达与安全间距。可在相册、文件、收藏等页面验证效果，但聊天维持现有列表滚动架构。若原生工具栏仍有背景，作为系统限制报告，不伪造“已全透明”。

M22 与动效整治在同一交付内验收，但不使用同一种技术方案硬套所有页面。

## 7. 原型与流程补齐

现有 V1 的十组 HTML 和流程保留为已交付历史证据；它们未覆盖本方案全部范围。后续在同一原型中增加语音、通话、通用控件、滚动定位、附件准备、备份恢复、隐私与主题／安全区域等必要体验入口，不要求机械增加为二十二个孤立页面。

可复用交互通过代表场景加调用方清单覆盖；具有独立操作模型的语音、通话等必须单独可操作。补齐正常、取消、反向、失败、减少动态效果及立即清理路径，流程说明与原型一致。

原型模拟必须标注：系统键盘、原生通行密钥提示、浏览器工具栏、真实音视频和真实恢复不能以模拟效果替代验证。新增原型效果与现有 V1 的实际审阅确认是正式实施前的设计依据；本方案不将用户要求“形成完整方案”记录为这些效果已经通过。

## 8. 一次性实施与交付流程

1. 核验最新主线与独占工作树，补齐页面、组件和状态检查表；整合主线新入口。
2. 补齐受影响的原型与流程，在同一份材料中确认完整体验，不重复询问已确定的范围和一次性交付要求。
3. 完成共享动效基础，再接入各模块；开发中定向验证，持续检查全部调用方。
4. 所有覆盖项完成后冻结同一候选，执行整体验收与必要修复，不交付仅完成部分模块的版本。
5. 在适用设计确认和正式实施授权完成后，依仓库流程提交、PR、CI、合并；生产发布仍以精确提交单独确认。

以上为依赖顺序，不是多批交付。设计阶段只维护本需求材料，不能因计划包含业务页面而提前修改正式代码。

## 9. 验收与完成标准

### 交互正确性

- 每项至少覆盖正常、取消／反向、连续操作；异步项增加失败、重试、过期结果；数据页面增加空态、加载、内容和错误。
- 发送期间继续输入、收到消息、媒体尺寸更新同时发生时，草稿、锚点和消息身份正确。
- 打开后立即关闭、关闭途中重开、快速前进返回、手势回位途中再次拖动，无跳回起点、残留遮罩、错页和失去焦点。
