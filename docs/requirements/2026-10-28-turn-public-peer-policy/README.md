## 根因与修正

1. 新站 HTTPS、WebSocket、TURN UDP／TCP 监听及凭据认证成功；原生浏览器取得公网 relay 地址，但不能建立媒体。独立 TURN 请求定位到 CREATE_PERMISSION 403。
2. 固定镜像 coturn 4.18.0 的地址范围检查把未指定端点视为通配符（[上游实现](https://github.com/coturn/coturn/blob/4.18.0/src/client/ns_turn_ioaddr.c) 的 `addr_any`／`ioa_addr_in_range`）。因此 `denied-peer-ip=::` 同时拒绝公网地址。内置零地址检查已经拒绝 `::`；无需增加这条范围。
3. 相同固定镜像、相同配置的短生命周期隔离容器，仅监听新主机回环测试端口；未变更线上 TURN。原配置公网权限403，去除此项后两个公网地址允许，10／127／169.254／172.16／192.168／0 地址仍403。仅建立权限、不向第三方地址发送中继数据。
4. 删除该重复项，保留其他 IPv4／IPv6 拒绝规则和内置检查。实验室原有唯一主机白名单掩盖了拒绝所有地址的问题；新增实际认证分配及九个公网／禁止地址的权限回归，公网检查地址均在白名单外。移除实验室对整个10网段的额外放开，仅保留本机白名单。
5. 继续执行原有加密音视频、双向媒体、ICE 重启与停止采集验收。版本更新为 `2026.10.28.2`，保留原版本历史。该修复不承诺真机、跨网络或独立外审通过。
