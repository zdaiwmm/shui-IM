## 方案与证据

用户报告表情→键盘时聊天闪动、面板／输入栏先下移；键盘→表情冲高回落；工具→键盘先下移；微信WebView工具底部露壁纸；首次创建与受邀加入密钥页不符视觉规范。截图仅为缺陷证据，原图不纳入Git。

已确认V1：

1. 表情／工具→键盘：直接请求原生键盘，输入栏从当前绘制位置连续到键盘上方，旧面板原位渐隐。
2. 键盘→表情：键盘收起与表情滑入同时开始；不叠加两份占用、不先冲高后回落；有实测键盘高度时沿用它，首次使用有界回退。
3. 统一占位、列表锚点与呈现结算。底部阅读时消息随输入栏自然移动，历史阅读沿用现有聚焦／锚点规则；不制造离屏后重新定位。
4. 工具面板及网页可绘制底部安全区连续使用composer-panel-surface；主题和切换期间无透明缝。
5. 创建与受邀加入密钥页共用本地主题色锁插图、居中标题／说明、外置名称标签及底部动作。26px/600标题、14px/1.6说明、16px字段、R12及≥44px操作沿用P1；短屏先缩装饰，内容可滚动。

正式实现优先协调既有视口控制与面板呈现所有者，不另建原生焦点例外。不改变密码／通行密钥选择、WebView回退、系统认证、创建加入结果、加密、MLS、草稿持久化、恢复或设备权限。快速反向从当前画面续接；中文组合输入保留；隐私清理立即执行，减少动态直接到终态。网页无法控制原生键盘动画时钟和宿主工具栏，真机需独立验证。

调查位置：src/app.ts的open/closeMemePicker、close/toggleChatTools及beginListKeyboardLayout；src/lib/meme-picker.ts关闭即释放占位并移动输入行；src/lib/composer-panel-motion.ts独立退场；src/composer-panels.css透明表单背景和安全区；src/entry-experience.css与gateway-intro.ts。以上为代码假设，尚无本轮真机复现。
