QUIET ROOM / V1 · 待设计确认

每次操作，都有连续的去向。

以下为 flow.md 的可视化阅读版。入口为已解锁聊天；所有消息和回执均为模拟。

01 · 阅读与输入

用户浏览消息历史位置 / 最新消息
→
输入或切换面板原输入框持续挂载
→
保留草稿与锚点不因聚焦跳回最新消息

02 · 发送与重试

点击发送立即给按下反馈
→
本地安全保存正式实现仍使用原子事务
成功
消息进入列表只清除提交的草稿；保留新输入
→
等待服务端确认离线等待；重连复用原 ID
→
原位更新回执不重建气泡
失败
保留草稿和回复显示明确错误
→
再次发送不要求重新输入

03 · 引用往返

点击引用记录来源消息与位置
→
读取本机原消息不可用则留在来源并提示
→
定位并高亮可继续查看其他引用
→
返回刚才位置恢复来源锚点

04 · 收到新消息

正在看历史

保持位置 → 新消息数量提示 → 用户点击后再返回最新消息。

正在底部聊天

新气泡进入 → 保持贴底。用户向上滚动立即解除底部跟随。

05 · 菜单、媒体与表情

长按 / 打开图片选中消息不隐藏
→
执行操作或取消手势取消不提交
→
返回原位置来源存在时恢复焦点
打开表情保留文字草稿
→
连续发送面板保留；媒体提前占位
→
切回键盘保留分类与滚动位置

06 · 任意阶段的隐私清理

锁定 / 页面隐藏
→
立即取消动画与迟到任务不等待退出动效
→
清除可见消息与临时预览正式恢复沿用现有加密草稿契约

无闪屏与位置稳定的验收边界

  • 键盘与面板切换时输入框持续可见，顶部栏不移动；同一元素只由一套位置控制逻辑管理。
  • 连续发送或中途反向操作，从当前已绘制位置接续；旧动画结束事件不能移除新画面。
  • 消息、媒体、时间与回执预留稳定尺寸；回执变化不重建原气泡。
  • 历史位置的输入、收到消息和面板开合，保留可见消息相对列表顶部的位置。
  • 窗口大小、浅深色、减少动态效果、文字选择、取消手势和隐私清理均覆盖。

真实系统键盘、WebKit 合成层、真实媒体解码、加密持久化和多设备回执不由原型证明。正式实现还需浏览器专项与 iPhone 真机逐帧检查；不承诺跨设备绝对零掉帧。
