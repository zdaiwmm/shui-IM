## 当前方案：自动兜底 + 业务验证 + 统一找回

**用户只做创建、加入、恢复等业务操作；系统自动判定本机保护路径。空间密码仅在本机系统保护明确不可用时兜底，不作为用户可选择的方式。**

进入页面先静默检查已有空间和可探测能力。新设备优先使用本机系统凭据；明确不支持时，点击原业务主按钮后进入共用密码设置页。无法提前确认时，点击主按钮触发系统验证，实际 PRF 明确不可用后自动转入密码设置。取消、超时、临时故障仍停在原页重试，不自动切换方式。

P03 用于设置新密码，P04 用于打开已有空间，P06 用于输入已有密码确认具体业务。三者在原型导航中独立可见，P06 也可通过流程图直接进入。

欢迎页仍只有一个“创建私密空间”动作，受邀页只有一个“继续加入”，恢复码弹层只有一个“继续”。欢迎页原有两项找回入口保留位置，文案改为“使用设备密钥找回空间”“使用恢复码找回空间”。C01、C02 不再预告面容／指纹／锁屏密码或提前解释保护路径；实际进入 P03 才解释兜底原因。页面不出现“自己设置空间密码”、保护方式选择页或并列方案。

正式产品仍只新增一个完整密码设置页模板；P06 是共用局部验证弹层。原型另补现有业务入口的调用示例，以便评审。邀请半屏、空间列表、批准、恢复码保存继续复用；找回说明页去掉恢复对象选择，双方参与页复用现有确认按钮展示自动判定结果。既有 `P / R / C` 编号保持，方便与前一版评审对照。

## 自动判定规则

| 阶段／证据 | 系统动作 | 用户看到的反馈 |
| --- | --- | --- |
| 本机已有目标空间 | 直接读取原保护方式；不重新选择 | P04 的原系统按钮或空间密码输入 |
| 安全连接、WebCrypto、必要本地存储不满足 | 两条新建路径均失败关闭 | 原页说明环境原因；不进入密码兜底 |
| WebAuthn API 不存在，或支持的探测 API 明确报告本机平台验证器不可用／PRF 客户端处理不可用 | 新设备保护路径确定为密码兜底 | 原业务主按钮保留；继续后 P03 说明需要空间密码，不在入口增加提示 |
| 探测支持系统能力，或探测接口缺失／结果未知 | 暂定系统路径；不把未知当不支持 | 原业务主按钮；不预告具体验证动作 |
| 点击主按钮后，实际凭据用户验证有效且 PRF 输出有效 | 完成本机系统保护，继续原业务 | 原建房、加入或恢复等待状态 |
| 当前实际凭据明确不支持 PRF，或所需加密能力经完整检查确认不可用 | 自动进入 P03，不增加确认或选择步骤 | “系统验证未提供保护聊天所需的能力，已转为空间密码设置。” |
| 用户取消、超时、临时错误或原因不明确 | 原位允许重试；不改保护方式 | “本次验证未完成，请重试。尚未切换保护方式。” |
| 已有系统保护空间读取 PRF 失败 | 保留原方式，重试原环境或共同恢复 | 不能通过新设密码打开旧密文 |

### 能力探测的实际边界

本期可以自动分流，**不能承诺页面一打开就一定准确知道所选凭据能否提供 PRF**。客户端的扩展支持与具体凭据的支持不同；实际凭据的 PRF 能力需结合注册／验证结果确定。[WebAuthn 标准：客户端能力](https://www.w3.org/TR/webauthn-3/#sctn-getClientCapabilities)、[PRF 输出](https://www.w3.org/TR/webauthn-3/#sctn-prf-extension)。

实施时采用“页面进入预检 + 点击后的实际确认”：

- 预检复用安全环境检查；按能力提供情况调用平台验证器／客户端能力探测。探测 API 缺失、抛错、超时或信息不完整均记为未知，不永久标记设备不支持。浏览器版本和设备型号不作为白名单判断。
- 探测支持只表示系统路径值得尝试，不能宣布某凭据 PRF 一定可用。实际注册返回没有 PRF 结果也不立即判失败，需先完成当前代码已有的补读验证；成功后再继续业务。
- 原生创建／验证继续由用户点击触发，不在页面加载时弹出系统窗口，也不在点击后先等网络或异步预检再唤起系统。检测未完成时保留系统尝试，避免丢失用户激活。
- 自动兜底只依据明确不支持的结果；`NotAllowedError` 等原因不唯一的错误不能统一按不支持处理。无效认证、完整性故障、原空间无法解密等安全失败不能当作新建密码的理由。
- 不支持结果仅服务本次新设备保护流程，不写永久浏览器黑名单。环境变化、重进流程时重新探测；不自动重写已有保险库。

### 复用的步骤与边界

- **R01 空间列表**：当前保护材料可复用时仍直接新建；没有材料时走 P02 的自动路径。密码路径保留短时派生材料，不保留明文密码，不让其他空间常驻解密。
- **R02 邀请半屏**：创建成功直接进入原半屏；不插入恢复码保存页或邀请前新门槛。
- **R03 找回说明 / R06 共同恢复**：只修改前置选择与结果确认，详见 C07、C08；恢复协议仍区分需要重建与保留本机历史的参与方。**R04 恢复码／备份页面、R05 加入与设备批准**继续复用；六位码、两方批准、三设备上限和历史边界保持。
- **R07 浏览器目录识别**：仍依赖原可发现系统凭据及 PRF；空间密码不替代跨浏览器目录发现。已有本机密码保险库走 P04；没有本机数据时，使用已有设备邀请或共同恢复。
- 新建系统凭据只请求本机平台验证器，不主动提供扫码／USB 高级路径；现有邀请与恢复二维码属于独立业务，继续沿用。
- 遮蔽、锁定、恢复码准备及销毁按最新 main 契约执行；自动能力判定不延长隐私保留期限，不接受原流程取消后的异步结果。

### P06 内容与状态

- 标题“输入空间密码”；说明“请输入此空间已有的密码，确认后继续本次操作”；展示目标空间名与操作名。只有一个密码输入，支持显示／隐藏；没有“确认新密码”或更换保护方式入口。
- 主按钮随调用场景呈现：“验证并查看恢复码”“验证并下载备份”“验证并恢复数据”。同一验证组件，保留原业务的输入、文件预览与操作上下文。
- 错误：“空间密码不正确，请重试。”留在弹层，不执行、不放行后续业务。错误节流复用保险库原规则；原型仅示意“尝试次数过多，请稍后重试”，不定义新的次数或等待参数。
- 小屏保持验证与取消按钮可见，内容过长时在弹层内滚动；背景不响应操作。输入框 Enter 提交，Escape 取消。
- 验证中：主按钮为“正在验证…”并禁用重复提交；仍可取消。取消清除输入与本次请求，只回原调用步骤；旧版入口“取消并锁定”。
- 空间锁定、会话／目标／调用操作变化：拒绝迟到结果，清除密码与证明；再次打开原空间后重试。一次成功仅继续发起的操作，不给其他业务批量授权。
- 恢复码显示、导出文件、恢复内容等按原生命周期处理，不增加永久“已验证”标记。后台任务不主动弹出密码。

正式实施须让 `confirmDeviceCredential` 按原保护方式执行真实再次验证。当前旧密码分支在会话存在时直接返回 `this.session`，不能沿用这个快捷返回作为新密码空间的确认；应使用原密码校验原包装与目标归属，按现有生命周期绑定当前操作。

## 统一找回：去掉前置选择，保留自动判断与结果确认

用户不需要判断“恢复谁”。找回页文案：“无论哪一方丢失空间，都可以在双方参与下找回。请各自在自己的设备上输入恢复码，无需交换。”只有“输入我的恢复码”主动作，码弹层只收当前参与者自己的码；双方材料不集中到同一设备。

当前代码的范围选择不只控制文案，还决定是否保留本机历史、是否创建新本机保护。`prepareJointRecovery` 明确要求协助者具有匹配目标空间、角色、原设备身份的已解锁会话，并完成成员状态同步、待发送与待上传检查。双方输入恢复码证明参与身份，不自动证明双方都丢失了本机空间。因此 v6 的统一入口仍保留内部恢复状态。

| 本次参与设备的已验证状态 | 自动处理 | 结果页反馈 |
| --- | --- | --- |
| 目标空间的原身份可正常使用，且满足协助条件 | 作为协助方；不重设本机保护，保留本机聊天 | “可以正常使用，保留现有本机聊天。” |
| 确认目标空间在本次设备无法继续使用／新设备没有该身份 | 为本次设备准备系统保护或自动密码兜底，重建空间身份 | “需要找回，旧记录可在完成后另行恢复。” |
| 有本机记录但尚未解锁／同步，或身份归属、状态不明确 | 先用原 P04／原同步路径查明；取消、超时、暂时失败不标成丢失，保留原材料 | “暂时无法确认本机空间状态。请先打开已有空间完成解锁与同步后重试，尚未执行找回。” |
| 双方空间均可正常使用 | 不发起无必要的共同重建 | “双方空间均可正常使用，无需找回。请返回原空间。” |

两端分别校验自己的码、目标与本机状态，通过已认证的共同恢复请求汇合各自结果；页面进入时不能预先判断对方是否丢失。QR4 中选择哪一个空间仍是目标选择，不能与“恢复谁”的删除混淆；多个空间时继续复用原空间列表。目标变更、状态变化或请求过期取消当前确认，迟到结果不执行。

**C08 复用现有共同恢复页与确认按钮。**原代码在范围未变化时可自动签署、完成；移除事先范围选择后，双方码通过时展示各自结果、相同编号及“其他旧设备需要重新授权”，再由双方确认同一份请求。按钮为“确认并找回空间”，没有新的对象选择或保护方式选择页。旧设备撤销、协助者可访问历史范围、找回方的显式历史导入、换码与隐私取消仍按现有契约执行。

实现范围不是只删除单选 HTML：需把 `selectedScope` 与受邀端无条件 `inherit` 改为各自已验证状态产生的恢复标志；最终签名仍绑定双方结果与目标设备。服务器不能根据登录／在线与否猜丢失状态；未认证的对方结果也不能当判定依据。`prepareJointRecovery`、`verifyJointSnapshot` 与共同批准必须兼容该判定，禁止默认 `both` 或因验证取消而清除协助方历史。本轮只设计、模拟该行为，尚未修改协议或产品。

原型“双方本机状态”下拉仅供评审模拟我方丢失、对方丢失、双方丢失、均可用与未知五种证据状态，不进入产品 UI。

## 四类设备反馈

| 生物识别／PRF | 新设备创建、加入和恢复 | 已有空间 |
| --- | --- | --- |
| 有面容／指纹，PRF 可用 | 自动系统路径；系统决定具体验证动作 | 按原方式打开 |
| 有面容／指纹，PRF 不可用 | 提前明确不可用或实际确认后，自动密码兜底 | 密码空间正常；系统空间重试／共同恢复 |
| 无面容／指纹，PRF 可用 | 自动系统路径，系统可能要求锁屏密码 | 按原方式打开 |
| 无面容／指纹，PRF 不可用 | 自动密码兜底 | 密码空间正常；系统空间重试／共同恢复 |

不把有没有面容／指纹作为路由判断。没有生物识别也可能有可用本机凭据；有生物识别也不保证 PRF。用户只完成系统提示或被自动呈现的密码输入。

## 密码与底层实施要求

密码独立于锁屏密码和恢复码；密码管理器用生物识别填入仍属于密码保护。P03 说明“以后打开此空间时输入这个密码。它不是手机锁屏密码”。原型以 12–128 字符示意；强度、KDF 与离线猜测风险须在安全实施设计中确认。错误密码不显示内容，忘记密码使用既有恢复码和共同恢复，不提供服务端重置旧密文。

当前 `createVault(..., 'password')` 生成旧 v1 保险库并走系统迁移，不能直接用作完整兜底。保持 v3 随机主密钥架构，新增密码包装；共用“准备保护材料／包装／解锁／再次验证”接口，兼容本机加密目录、恢复码、备份、恢复和旧格式。密码、派生秘密、主密钥与恢复码不上送服务器。自动兜底不得给原有 v3 密文增加未授权密码解锁途径。

证据来源：任务基线 `src/app.ts`、`src/lib/vault.ts`、`src/lib/platform-vault.ts`、`src/lib/browser-access.ts`、`PRODUCT.md`、`SECURITY.md`。视觉沿用 `DESIGN.md` 与现有共享 tokens、gateway、恢复弹层。业务交互可小范围修改，完整密码保护仍需要底层兼容工作。
