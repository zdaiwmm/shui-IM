## 行为与验收

- 预算属于同一设备、浏览器、站点下的可清理加密媒体，所有空间共用；沿用最近使用顺序和至少 64 MiB 历史／密钥余量，按浏览器实际可用配额进一步缩小。无预分配。优先释放可替换项，保护持久历史、密钥、恢复导入原件与进行中的收发。完整核验并成功落盘后才记为已缓存。空间不足或站点数据被清理后允许回源。
- 发送复用上传密文，接收按需取件。收发成功、完整落盘及归档成功分别报告。重开、刷新或再次解锁时，完整命中由本机校验播放，验收以视频分块请求和正文下载字节均为零为准。旧封面与受支持的播放副本分别识别；仅封面或损坏副本不能冒充完整原件。首次下载中断后只补缺块，损坏缓存受限重试。既有显露与已读规则沿用。
- 单视频上限按原字节；密室与全站附件额度以含认证开销的预留字节计，全站在线附件总额保持 10 GiB，其他格式沿用既有限制。加密服务不能从密文验证真实视频格式；实施需区分可信客户端类型检查、服务端通用上限及防滥用。兼容性或预算不足提前提示，服务端原子预留处理并发。大视频需要有界内存、完整认证、原长度及摘要验证，覆盖备份、恢复、导出、发送草稿及异常清理。归档独立计量；不因附件改额隐式放宽归档。大视频归档超额要能报告未备份，真实占用与上限另行核验。
- 播放中轻点唤回不暂停；暂停、播完、出错或键盘操作时显示合适的操作。键盘焦点、进度拖动优先。关闭、翻页及锁定停止并清理，系统原生全屏由系统接管。

## 实施与验证

回归等级 full，涉及密文存储、设备能力、客户端缓存、备份及播放器。收发端使用既有 AES-GCM 分块和整件摘要，未加入转码。128 MiB 以上聊天视频按需取原件；旧端混用禁止发送超过 256 MiB 的视频。10 GiB 为单站点本机可清理预算，给密钥／历史保留 64 MiB。有既有归档或备份空间不足时，不能凭发送成功认定归档成功。

专项验证包括真实渲染器、发送者本机原件、收件端刷新后零分块请求、分块中断续取、旧播放副本兼容、限额边界、锁定与两个浏览器的配额压力。完整本地检查首次因三项交付工具测试在五秒内未完成而中止，冻结后降低本地并发重验。合成大文件与物理 iPhone 证据分开，生产状态以发布回读为准。

2 GiB 原件专项见 [verify-large-video.mjs](verify-large-video.mjs)，在仓库根目录运行 `node docs/requirements/2026-11-04-video-cache-playback/verify-large-video.mjs`。使用普通 Chromium 临时配置、真实可解码的合成 MP4、临时原件存储与 1024 个真实加密分块。第一版整件摘要通过但浏览器组装的大 Blob 不可读；停止旧提交的本地浏览器全量运行并改为具有背压的单一字节流，整件认证后才发布播放来源。受限浏览模式可能无法暂存完整可播放文件，此时提示释放空间或使用普通窗口，保留健康密文以便重试。
