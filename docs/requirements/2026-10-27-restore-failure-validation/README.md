## R1：修复前的小范围验证

使用真实本地API、归档加密／恢复、IndexedDB、私有目录与原件解密路径，全部为合成数据。每个目标先保存一条共享消息、一条私有文件记录和1024字节原件；来源含文字、跨2MiB分块的约3MiB文件及64KiB文件。逐原件核对SHA-256，刷新重开后重试与重复恢复，并确认未完成导入未进入再备份。

[observations.json](observations.json)保留修复前19项完整观测及原探针摘要，不用后续结果改写。原探针已按同摘要归档到公共Git证据目录；[当前正式回归](../../../tests/restore-original-cleanup.e2e.mjs)由既有room-archive-lifecycle入口顺序纳入。首轮16项后遇合成房间创建限流，未改产品限流，改为每引擎独立服务后补缺项及两项原生配额对照。

## R2：最终修复契约

验收为：故障不发布半份消息、不留下本次未引用的逻辑原件；已有记录、原件与其他恢复任务不受损；刷新、重试、重复恢复及配额内恢复可用。密码格式、MLS、设备与历史权限、既有页面、备份调度保持。

- 新导入为每次恢复的每个来源分配随机独立原件命名空间。其他新任务与旧客户端不能借用未发布范围；来源room+消息ID仍是记录身份。已有已发布副本复用原sourceScope，包含旧版按origin分配的范围，不迁移既有原件。
- 原件只在privateMedia保存一份，和小型run归属见证在同一保险库CAS事务写入。见证只含原件ID、密文记录SHA-256及是否为已发布副本的修复，不重复存储大块密文。逐块真实回读与完整文件校验保持。
- 全部验证完成后，消息、删除事件、目录版本及见证退役在同一事务发布；不再次复制原件。未发布内容不参与渲染、通知、回执或再备份。原件消失／见证变化或消息冲突中止整个发布。
- 失败只删除本run见证覆盖、密文仍一致的未发布原件。已发布原件、已发布副本的缺块修复及其他写入者替换后的原件保留。随机未发布范围是该归属规则的前提，后续不得改回按origin共享未发布原件。
- 意外关闭及旧版残留仅在持有恢复独占锁、全局保险库租约、可用锁清单且没有其他活动恢复时，完整认证扫描所有原记录引用后回收。保留隐藏／删除投影仍引用的原件、非私有范围及未知键格式；未知来源范围或无锁清单保守跳过，损坏记录／陈旧保险库失败关闭。
- 复用DB16现有库和原件认证密文格式，不升级／降级数据库。既有通用私有读取器按记录sourceScope读取；旧写入端可能拒绝重导入新命名空间的副本，不得以冲突为由覆盖或清理，新版幂等重试保留。

## 配额与验证证据

应用逻辑删除不等同浏览器立刻释放底层占用。Chromium[延迟回收说明](https://codereview.chromium.org/100013003)及[存储上下文源码](https://chromium.googlesource.com/chromium/src/+/c0811f657d5ae8c42a9fb827e7e36e7e58a16bab/content/browser/indexed_db/instance/bucket_context.cc)解释回收与内存模式关闭条件的区别；仅凭源码不宣称本次Linux底层原因已完全定位。

原生配额用例采用每项独立落盘的临时浏览器档案；普通故障仍覆盖内存上下文。先立即断言逻辑原件／暂存为0，再不打开IDB地观察实际使用量，最多15秒必须回落到合成旧数据范围（小于1MiB），之后只发起一次小恢复。低配额对照阶段始终同一5MiB，不刷新、不清库、不强制GC、不增加配额或自动重试恢复。完成该阶段观测后，另设64MiB仅验证足够空间下的刷新／重试／去重，不移用为低配额成功证据。15秒是测试预算，不是产品对浏览器回收时限的承诺；未释放时浏览器仍可拒绝新写入，需稍后重试，不清其他数据规避。
