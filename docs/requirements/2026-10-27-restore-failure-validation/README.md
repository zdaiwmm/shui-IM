## 范围与实验

复用实际本地API服务、房间归档加密/恢复函数、IndexedDB、私有目录与原件解密接口。每个目标库先保存一条已有共享消息、一条已有私有文件记录及其1024字节原件；被恢复的合成归档包含文字与跨2MiB分块的约3MiB文件。输出只保留数量、大小、错误分类和完整性布尔值，不保存恢复密钥或正文。

- Chromium和桌面WebKit：正常恢复、写入前取消、第一块原件持久化后取消、后续网络读取失败、原件写入配额异常、最终原子发布中断、两个不同归档先后取消。
- Chromium额外使用原生`Storage.overrideQuotaForOrigin`：5MiB配额在目标库首次写入前设置，由浏览器实际产生QuotaExceededError；不通过伪造storage.estimate得出结果。
- WebKit配额分支使用可控事务中止并呈现QuotaExceededError；不宣称WebKit原生空间耗尽。
- 刷新后通过实际保险库解锁路径重开，再恢复相同归档及重复恢复；逐原件解密并核对SHA-256，验证未完成导入未进入再备份。

脚本：[后续正式回归入口](../../../tests/restore-original-cleanup.e2e.mjs)；脱敏逐项观测：[observations.json](observations.json)。R1历史共19项完整观测，observations.json保留修复前结果及原探针摘要，不用后续回归改写。首轮在16项完成后，最后一个WebKit用例的合成房间创建触发测试服务限流；未修改产品限流，改为每引擎独立测试服务后仅补完缺项，再执行两项原生配额对照。没有以该夹具失败作为恢复失败结论，也没有重跑产品完整门禁。

## 已确认结果

| 边界 | 观测 |
| --- | --- |
| 既有数据 | 所有已完成观测中，共享消息、既有私有记录和原件均保持一致；原件解密及摘要相符。 |
| 未完成内容 | 故障后可见私有记录仅保留既有一条；发布版本未改变，消息暂存清空，未完成内容未进入再备份。 |
| 原件残留 | 第一块原件落盘后取消或网络失败，残留一个没有已发布消息引用的加密原件块；刷新重开后仍存在。最终发布事务中断可遗留全部三块。 |
| 累积 | 依次取消两个不同归档，未引用块从1增至2；序列化加密记录合计约7.11MiB。这是逻辑记录体积，不是物理磁盘或内存测量。 |
| 原生配额失败 | Chromium 5MiB上限下，恢复大归档产生原生QuotaExceededError，仍残留第一块原件；原库数据保持不变。 |
| 实际功能阻挡 | 相同5MiB上限、相同规模既有数据下：无残留的对照库成功恢复含约1MiB原件的小归档；有失败残留的库恢复同一小归档报QuotaExceededError，旧数据仍完整。原生配额报告的使用量分别约1.87MiB和3.64MiB。 |
| 重试 | 提供足够配额后可成功重试，原件摘要一致；重复恢复没有重复记录或重复原件。成功恢复另一个归档不会自动清理旧失败任务的未引用原件。 |

根因对应现有路径：`room-archive.ts`先将原件写入长期`privateMedia`，随后暂存消息，最终统一发布消息；`discardPrivateArchiveStaging`仅清除消息暂存，未建立本次任务新增原件的回收边界。消息原子发布保护有效，但失败原件占用可以持续并妨碍后续恢复。

## 结论与下一步

确认存在客户端恢复失败后的存储残留与可用性问题，值得优先讨论修复。当前实验没有发现既有数据损坏、半份消息对外可见或未完成导入被自动备份。修复需要保护已有原件和其他任务引用，不可直接删除整个来源命名空间；R1没有实现清理、改协议或做备份追赶优化。

本结论限于合成数据、本地真实浏览器及上述故障点；没有实体iPhone、实际触控取消、真实磁盘耗尽或生产数据验证。5MiB仅是受控触发条件，不代表浏览器默认配额。用户随后已授权下列R2修复，R1证据边界仍保持。


## 修复 R2：范围与验收

用户明确「完成修复并合并发布生产」后实施；仅处理客户端恢复存储生命周期，保留既有页面、归档密码格式、普通设备历史权限及备份调度。验收为：故障不发布半份消息或新增长期原件；已有共享／私有记录、原件与其他恢复任务不受损；失败后刷新、足够空间重试、重复恢复及配额内的小归档恢复可用。

- 新原件按随机run ID与消息共同放入现有DB16暂存库，保持原件认证加密范围；完整校验后在同一IndexedDB事务移动原件、发布消息及目录版本。不新增数据库版本，不重新加密或保存第二份长期原件；既有同字节原件直接复用。
- 取消／失败仅丢弃本run暂存。意外关闭留下的暂存在后续恢复开始时回收。清理失败不改报成功，未发布内容不会进入渲染或再备份。
- 旧版长期残留仅在持有恢复独占锁、全局保险库写租约且锁清单没有其他恢复任务时处理；完整认证扫描所有已发布原记录，以来源及原件分块引用判断。保留已发布原件（含已隐藏／删除投影的原记录）、非私有范围及未知键格式；不按整个来源目录删除。缺少锁查询、其他活动恢复或未知来源映射时保守跳过；损坏记录／陈旧保险库失败关闭，不作猜测删除。
- 原件发布使用既有保险库CAS，并比较并发写入的原件记录；冲突中止整个导入，不覆盖其他写入者。旧客户端的恢复锁名称继续协调，网络等待不持有保险库写租约。

正式回归覆盖两浏览器的取消、网络失败、写入配额中断、最终事务中断、连续不同归档取消、取消已成功归档重导入、刷新／重试／去重及逐原件摘要。Chromium原生5MiB配额验证失败无残留且后续1MiB小归档成功；8MiB配额验证可容纳的完整归档直接成功；预置旧残留后验证安全回收。另验证其他活动恢复、未知键／非私有范围、无锁查询、并发原件冲突及损坏原记录保护。入口由现有room-archive-lifecycle浏览器门禁顺序纳入，不并发占用同一测试服务。

当前交付证据：修复后的专项23用例（Chromium14／WebKit9）及两引擎各六类清理保护检查通过，未引用原件为0、原件摘要均一致；最终审阅进一步收紧未知UUID键保护并增加无锁归属／刷新断言，由最终完整门禁复验。首轮专项在旧残留分支发现键游标不能直接删除，修正为对象仓库删除后专项完整通过；历史失败保留。类型检查通过。待最终候选完整本地门禁、PR CI及精确main完整CI；生产精确SHA确认、只读预检与正式发布分别取证。真实iPhone、触控取消与物理磁盘耗尽未验证，WebKit配额为受控事务故障；不扩大自动化证据。
