## 已确认方案与设计范围

1. 保留设置中的备份数据、恢复数据两个页面。备份提供本地加密文件和自动云端加密备份；恢复提供本地文件及云端归档，两种方式并存。
2. 自动备份采用开关，作用于当前私密空间中的本人已授权设备。首次开启先说明隐私边界并确认；新用户默认关，已有用户如实显示既有开启状态。显示成功时间、覆盖范围、暂停与失败，不承诺常驻后台运行。
3. 关闭停止后续历史备份，不删除已有云端备份；离线设备收到设置后停止。空间恢复所需的加密身份材料独立维护，不能因关闭聊天备份而失效。
4. 同一空间、同一参与者、持有有效恢复授权和解密材料即可跨设备恢复；不能仅按来源设备拒绝。云端默认聚合本人已授权可读归档，旧归档缺材料时补码或仅恢复已授权范围。普通新增设备不自动获得旧历史。
5. 本地文件只含本机已有记录和可用附件，包括已从其他设备恢复到本机的内容。显示缺失附件，系统交接不当作文件保存成功。
6. 恢复先验证、合并去重和处理隐藏投影，再确认范围、导入及回读。错误、取消、离线和锁定均明确反馈；保留已导入片段，不覆盖冲突内容。创建者的保险箱与受邀者权限保持分离。

隐私说明：平台接收密文及必要元数据，不保存恢复码及解密密钥；恢复材料泄露可能暴露归档，丢失无管理员绕过。附件依赖原件仍可用；不承诺零元数据、绝对终端安全或远程销毁已有副本。

## 实施前现状与必要设计（历史）

- `src/app.ts` 现有自动备份无用户开关，旧页面藏于 `#legacy-backup`；`src/lib/cloud-backup.ts` 有多归档恢复能力。
- `src/lib/local-history-backup.ts` 的 ownArchives 依赖原设备保留下来的归档密钥。QR4 目录本身不等于本人所有设备历史目录。不得用 UI 改名或取消设备校验替代授权。
- 正式实施需设计经过认证的本人备份目录、设备独立贡献、撤销/轮换、并发开关版本与离线同步，以及恢复授权获取机制；不能只凭 roomId/role 发放密钥。
- 本地文件跨设备恢复所需的密钥封装及旧文件兼容须另做协议验证。原型输入框只示意取得恢复材料，不证明现有总码已经覆盖所有设备，也不承诺所有旧文件仅凭单枚码即可离线恢复。
- 拆分聊天历史云备份与身份 checkpoint，确保关闭开关不阻断本地导出/导入或空间恢复。关闭时服务器与旧客户端如何停止后续历史写入必须验证。
- 不改双方共同恢复及旧设备撤销流程；此处恢复历史与身份替换是两个不同操作。当前新增设备无加入前历史的契约只在持材料显式授权恢复时例外。
