# 最小需求记录模板

仅用于跨模块功能、架构或重大不确定性等复杂需求；小修复由 PR 与验证结果记录。
本模板的一份记录兼作方案、必要计划、进展和交接，不另建等价任务卡。
澄清阶段可留在会话中；需要正式记录时，将本模板的适用字段保存到
`docs/requirements/<需求编号>/README.md`。删除提示文字，不复制每轮聊天。
同一需求持续修改同一份记录；不适用项写明原因，未知项不得填为已确认。
流程与权限见[工作流](../context/workflow.md#需求澄清与设计确认)，
材料遵循[轻量保存](../context/workflow.md#需求材料的轻量保存)。

## 确认与授权

| 节点 | 版本及范围 | 用户确认时间、最小脱敏摘要与可核实来源 | 下一步权限／未决项 |
| --- | --- | --- | --- |
| 未决关键方案 | 仅填写适用范围；已有批准方案直接引用 | 记录已有确认或确实尚缺的确认 | 设计／实施／仅讨论 |
| 必要原型或流程 | 无设计决策时省略 | 复用已确认版本，不按技能节点重复审批 | 对应范围的下一步 |
| 变更／本次例外 | 无则写无 | 仅记录实际发生的确认 | 写明受影响范围 |

不要求固定确认口令；可记录实际可访问的会话／消息定位，未提供定位则明确说明，
不得编造来源。版本标识须能定位被审阅内容（明确标签与 Git 提交或内容摘要），
修改后不得沿用旧确认覆盖新行为。需求、设计、实施与发布授权分别核实。
