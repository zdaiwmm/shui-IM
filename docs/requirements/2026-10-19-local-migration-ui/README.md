## 原设备迁移设计

1. 原会话证明本人的旧成员角色，重新认证本机应用锁，绑定／复用本人根身份。各自妥善保存本人助记词，不让两人的助记词进入同一操作环境。
2. 原设备先准备独立、空的迁移存储范围与随机暂存主密钥，仅加密存于旧保险库内部，不上云。恢复请求仍交给已经获准的原设备；完整验证后才为最终共同切换生成随机逻辑设备密钥。迁移不增加普通设备名额或扩大权限。
3. 固定双方根、原空间／角色、generation、目标公钥、源记录清单及签名历史head；生成新版仅数据备份，原设备私钥／MLS发送状态／根秘密不上云。备份完成必须从云端回读对应密文。
4. 双方分别批准对方同一次历史请求并实际参与解密。将云端备份解密到独立暂存范围，禁止用原存储中的明文／已解密记录伪装恢复成功。逐记录核对ID、序号、内容摘要、投影及附件原件；本机重新加密持久化后回读，覆盖聊天及本人原有保险箱权限。
5. 缺块、冲突、不可回读、原件丢失、容量不足、离开／锁定时暂停，保留原数据及已验证的加密进度；不显示迁移成功。未备份且原设备也无法取得的旧内容不能凭空补回，必须阻断完整迁移并明确缺项。
6. 两人均验证完整当前快照后，各自核对同一六位安全码并重新认证确认。新消息／投影或附件变化使受影响快照及确认失效，先补齐；最终切换需短时协调发送与持久待发／草稿，不能丢弃用户在切换期间的输入。
7. 事务切换同一个空间到新的MLS generation并核对服务端回执、本机目标记录和加密目录。只有匹配的双方批准与完整性回执才可退役该间旧在线恢复包与旧token；本机继续使用原历史命名空间／主密钥和偏好／草稿归属，保留全部已验证记录；暂存区只证明云端恢复完整，不冒充最终历史副本，签名回读后仅清理暂存区。不合并其他空间。切换响应丢失先回查同一事务，即使批准期限已过也先读取最终回执，不重建身份／重复切换。服务端已切换后失败进入接续，不能声称已回滚服务器。
8. 原设备继续展示已核验历史；其他原授权设备按现有新generation规则重新接入。迁移验证／最终generation不能因内部候选累计产生三台上限假失败，也不能泛化放开普通新增设备历史边界。

独立本机恢复可验证加密备份与落盘完整性；它不能证明另一款浏览器／另一台实体设备的兼容性。真实iPhone／iOS27／Safari验收及独立安全审阅仍单列。

旧受邀方MLS缓存里的保险箱行通过认证的`omittedSafe`序号覆盖保持聊天链连续，备份不包含对应保险箱内容／清单／原件；格式拒绝空洞、重复及重叠，创建者恢复拒绝该排除范围。完整迁移要求云端链、原设备仍保留的记录和有权限的删除投影一致；本机或云端不可补齐的缺项继续阻断，不跳过验证。
