## V1 方案与边界

### 草稿

- 输入事件完成前同步生成并写入**本机密文检查点**，覆盖新增、替换、清空和输入法中的当前输入。现有 IndexedDB 偏好记录继续承载滚动锚点和其他投影；检查点专门填补异步提交被刷新中断的窗口。
- 只在已成功解锁、草稿读取完成后开启编辑。通过现有 master key 派生用途隔离的草稿密钥，在解锁运行期留存于内存；采用锁文件已有的 AES-GCM 实现和每次随机 nonce。检查点绑定来源、空间与设备，正文及版本信息受认证加密保护。密钥、明文和检查点均不上传，不进入恢复包或云备份。
- 浏览器同步存储保存密文；它与现有本机保险库受同一来源约束。重新打开仍要用原保护解锁。锁定同步遮蔽并清除运行期草稿密钥，不等待后台写入。删除空间／清理本机数据必须清理对应检查点，损坏记录不能默默恢复旧草稿。
- 持久发送成功后仅清除提交的草稿版本；发送期间的新输入、同文本 ABA 及失败草稿保留。异步旧保存不能覆盖较新检查点；多标签页分别标识写入者并验证当前运行期归属，防止旧文档或旧空间的迟到写入复活草稿。
- 保存失败沿用现有错误反馈，不宣称已保存，也不以写明文作为降级。容量、损坏、并发和清理行为必须有自动回归；若现有安全机制不能充分支持此设计，暂停受影响部分并更新方案，不扩张密钥或权限边界。
- 不改消息加密、MLS 棘轮、消息 ID、签收、附件、设备历史、恢复权限或隐私遮蔽期限。不降低现有锁定保护以等待保存。

### 邀请

- 从列表创建或重新邀请的弹窗关闭后，回到空间列表；待加入项仍在，保留可用的滚动和键盘焦点。桌面恢复现有侧栏，窄屏恢复抽屉。沿用当前外观、文案和手势。
- 区分列表入口与初次创建入口：初次创建无列表返回上下文时保留当前聊天底层，不扩展既有首次使用流程。
- 关闭按钮、遮罩、Escape、有效下拉共用返回路径；锁定、空间切换、过期销毁及对方加入优先。旧回调不得恢复过时列表或覆盖已完成的聊天。
