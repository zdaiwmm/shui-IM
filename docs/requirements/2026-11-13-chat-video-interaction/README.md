## 2026-11-16 链接视频验收修复

修复基线为 a591e8fa163aa4b104614811c548d5586cf90920，独立工作树 link-video-fidelity-20261116、分支 fix/link-video-fidelity-20261116。原型仍为已确认 V3，SHA256 `50e72193e27b43d45854e80274278dbb59d3be6e0af1f5b1efc46e06d3869074`，不重新选择视觉方向。

用户反馈「仅下载」和「下载并发送」均提示后台尚未更新。真机为 iPhone16,1／iOS 27.3／Safari：实际客户端是 2026.11.16.1，后台已激活且准备探测返回 ACK，但带 CryptoKey 的源任务没有 ACK；同样的 154 字符合成任务在桌面 Chromium／WebKit 可被接收。合成不存在任务的探测没有请求原视频、没有新增传输记录，不能归因于用户没有更新页面。

本轮改为消费式交接每任务独立的 32 字节源密钥缓冲区：页面转移缓冲区所有权，后台立即导入不可导出的 AES-GCM encrypt-only CryptoKey，并在确认／进入队列前清零；失败和拒绝路径也清零，不把源密钥、来源网址或明文视频放入传输数据库。准备握手增加 sourceKeyBytes 能力，旧后台只回 version 1 不足以启动新源任务，等待升级和 controllerchange。旧 CryptoKey 客户端在可用浏览器上仍兼容；不改变任务 ID、nonce、ETag／Range、显式取消、保险库或聊天授权。

另修复一个确定的更新入口漏洞：语言初始化可晚于 window.load，原更新器此时错过注册。按 document.readyState 立即或单次注册，并禁止导入脚本更新缓存。这是相邻升级修复，不能替代上述真机交接证据。

原弹窗实际使用横向条目、普通输入框及反向主次操作，未忠实实现 V3。本轮恢复链接图标／清空、双列封面、多选序号、全选与计数、分项任务进度和发送主操作，并修正完整样式层叠覆盖标题的问题。我的下载及私有锁含义沿用原契约。
