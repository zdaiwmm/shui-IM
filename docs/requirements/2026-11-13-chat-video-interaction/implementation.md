# 胶囊状态切换规则

业务完整执行每个必要步骤，视图只提交最新快照。跳过的是未展示的中间画面，不能跳过下载校验、落盘、加密或提交。

| 情况 | 必须实现的行为 |
|---|---|
| 一帧内连续收到下载、保存、加密 | 只绘制最后一次有效快照，不为前两个状态分别启动动画 |
| 过渡尚未结束时又收到新状态 | 用最新状态替换待显示目标；旧动画回调不得写回旧文字、图标或进度 |
| 同一阶段连续进度变化 | 更新同一个环形进度与底色，不重建胶囊，不重播入场或箭头动效 |
| 瞬间完成 | 可以直接从下载跳到“已保存”或“已交给聊天发送”；是否显示“已发送”仍由实际确认事实决定 |
| 发生失败 | 立即提交失败状态；停止表示处理中的动效，保留详情和重试，不等待普通过渡结束 |
| 更高优先级提示占用胶囊 | 后台只保留最新任务快照；任务重新取得提示位时直接显示最新状态 |
| 后台恢复或面板重开 | 从控制器读取当前快照，不播放期间积压状态 |
| 锁定或失去任务归属 | 同步清理展示、动画和回调，不能等退出动画完成 |

调度采用一个 requestAnimationFrame 和一个 latestSnapshot 槽位，不创建状态数组或 FIFO 展示队列，不设置最短状态停留时间。普通过渡可沿用 V3 的 260ms；更新时从当前可见值接续。每次任务批次、重试轮次和视图挂载均有递增版本号，旧异步结果与动画完成回调必须校验版本。

下载、上传且总量已知时显示真实阶段百分比，环形进度与文字一致；保存、加密、提交及未知总量用不定进度弧段，不编造总进度。不同阶段允许重置对应阶段进度，必须同时更新阶段文字。终态与失败状态直接更新，不被进度采样节流阻塞。减少动态时取消流光、箭头往复和旋转，保留静态进度、图标与文字。

## 交互规则

按当前工程二进制容量口径，自动下载阈值设为 30 × 1024 × 1024 字节，即 30 MiB；界面沿用 MB 显示。等于或超过阈值均需显式点击下载，小于阈值保持原有可见范围加载策略。阈值只控制自动网络下载，不修改 128 MiB 的缓存单件策略、2 GiB 的视频大小上限或设备能力门槛。

进入聊天、恢复历史锚点、滚动露出、列表重渲染和相邻媒体预加载，都不得自动请求达到阈值的视频原件。已有完整且有效的本机缓存直接使用，不重复下载；只有封面或部分分块缓存仍算原件未完整下载。

| 状态或操作 | 行为 |
|---|---|
| 原件未下载 | 渲染固定比例视频气泡，中央为独立下载按钮；左上显示已知的真实时长 |
| 点击下载按钮外、气泡卡片内 | 只切换封面遮罩；有可信封面时揭开，没有时显示中性占位和“封面暂不可用”，绝不触发原视频下载 |
| 点击中央下载按钮 | 显式授权当前视频原件下载，中央显示进度及取消；不能同时冒泡触发揭罩 |
| 下载中点击周围区域 | 仍只切换封面遮罩；不取消、不重复启动、不自动播放 |
| 下载完成 | 同一个气泡原位切换到播放按钮，保留时长、封面遮罩状态与列表锚点；不自动播放 |
| 下载失败或主动取消 | 停止处理动画，原位提供重试或下载；保持气泡尺寸，封面揭示与原件下载状态分开保存 |
| 已完整缓存 | 按现有播放和遮蔽规则使用本机内容，不能无故重新走网络 |
| 锁定或离开密室 | 中止下载、解码及揭罩，撤销资源；再次进入恢复默认遮蔽，不后台补播状态 |

时长或视频比例尚未知时保留稳定中性占位，取得可信元数据后补齐；不能把虚构的 00:00 当作未知时长。

- [ ] 在统一策略入口判断，并检查缓存命中、微任务 hydration、历史锚点恢复、IntersectionObserver 及相邻预加载等旁路；本机不完整缓存不能落回自动网络补拉。

## 任务 7B 下载原件前取得封面和时长

现有服务器消息不携带视频封面，封面仅在本机于原件完整校验后生成并加密缓存，旧附件格式也没有时长。因此，“首次接收且原件未下载时即可揭开封面并显示时长”不能只靠修改按钮或阈值完整实现。

拟采用新视频的独立端到端加密展示附件，包含有界封面和真实时长，由发送端取得完整本机视频后生成；接收端可只取这份小型展示数据，不请求原视频。服务端只持有密文，不使用公开封面 URL，也不发送给外部抓图服务。

- [ ] 本轮用户授权现有方案实施，按方案中的独立端到端加密预览推进；同步更新旧“不上传封面”的相关产品与安全契约，使其明确为不上传明文封面、加密预览须经过能力协商与限额校验。当前尚未实施，不将方案认可写成协议或安全验证通过。

- [ ] 确认后制定具体消息版本、能力标识、受限封面尺寸与字节预算、元数据校验规则和旧设备策略；不得向旧设备严格校验的现有结构直接塞入新字段。

- [ ] 封面与时长必须绑定原视频身份和摘要，经端到端认证、解密和独立完整性校验后才可展示；未揭罩前不得把清晰封面短暂绘制到可见层。

- [ ] 能力不满足的发送使用旧格式；接收端仍遵守 30MB 手动下载规则，封面和时长未知时明确降级。旧历史没有预览数据且本机没有缓存时，不自动回填或下载原件补封面。

- [ ] 增加跨版本、混合设备、预览篡改、超限封面、错绑视频、遮蔽与锁定清理测试，并按仓库协议和隐私变更流程验证。

这一步与此前“仅在本机提取时长、不修改消息结构”的范围不同，需要单独确认，但不阻止任务 7A 的策略和气泡交互实现。

# 任务 8 网页隐私遮蔽和可恢复传输

## 已确认范围和现实边界

用户已确认将“内容立即遮蔽、安全保存进度、恢复续传”的网页方案纳入本次实施。桌面浏览器在未休眠且允许执行时可继续任务；移动浏览器切后台或熄屏后可能挂起，因此验收目标为安全暂停与恢复，不声称持续后台完成。原生 URLSession、原生后台计算和系统通知不在本次范围。

当前 visibilitychange 默认触发 lockNow / cleanupRuntime，链接视频也受同一运行信号中止；上传已有分块及服务端已传索引查询，但完整持久任务和重载恢复仍需补齐，不能把现有分块接口写成已完成恢复能力。

## 结构与接口

新建 `src/lib/transfer-task.ts` 管理传输事实、阶段与恢复；新建 `src/lib/transfer-checkpoint.ts` 管理经现有保险库机制加密的检查点。修改 `src/app.ts` 的 visibilitychange / freeze / pagehide / lockNow / cleanupRuntime，`src/lib/link-video-task.ts`，`src/lib/file-crypto.ts` 与必要的 vault / 缓存适配。修改前先读 SECURITY.md 中相应传输、隐私与原子提交契约。

接口约定：`checkpoint(taskId, reason): Promise<void>`；`resumeAfterUnlock(session): Promise<void>`；`cancel(taskId): Promise<void>`；`disposeView(): void`。隐藏视图只移除展示订阅，不能通过 disposeView 暗中删除任务；完整任务取消必须走 cancel。任务控制器不得把完整 VaultSession 交给非解锁态的传输执行器。

状态区分：运行中、等待浏览器恢复、等待解锁、等待重选原件、网络中断、空间不足、已交给待发箱、已确认完成、显式取消。暂停、失败、取消和完成不能混用。

## 必做行为

- [ ] 切后台立即覆盖聊天、封面、标题与敏感预览，停止播放；恢复前不闪出旧内容。应用锁与身份验证仍生效，遮蔽不能冒充已销毁全部密钥。

- [ ] 把任务记录、已保存素材标识、远端已确认分块和本机完整密文分块保存为可恢复检查点；复用原 clientMsgId、blobId、加密参数与已生成密文，不能重试推进两次 MLS。

- [ ] 已加密完成且满足授权隔离的上传可以脱离聊天解锁会话继续；只保留任务所需的最小凭据和密文，不保留房间主密钥或可读取聊天的会话对象。若当前授权机制不能安全隔离，则锁定后暂停，解锁后恢复，不靠保留整份会话伪装安全。

- [ ] 尚未完成的加密在锁定或系统挂起前尽力保存已完成检查点；不写明文临时文件、不将明文或解密材料放入普通 localStorage、Cache API 或日志。不能依赖 pagehide 最后一次回调才保存关键进度。

- [ ] 安全保存的完整本机素材可免重选；只存在内存 File 且页面被回收时，显示“等待重新选择原文件”，保留已上传分块并校验文件身份。不得无条件承诺所有发送都免重选。

- [ ] 聊天附件下载保留密文分块，恢复后继续缺失部分；部分缓存只能作为候选数据，完整解密及原件摘要校验前不展示原件。空间不足与损坏缓存按现有边界失败关闭。

- [ ] X 直链下载只有在源站支持 Range、内容身份稳定、206 / Content-Range 与预期一致时允许续接。临时接收内容必须即时加密保存；不支持续接或源内容变化时明确提示重下，不能拼接不同视频或保留明文缓存。

- [ ] 恢复运行后先读检查点及服务端已确认状态，再调度未完成任务；失败项单独重试。重新进入聊天不会因此自动下载新的 ≥30MB 视频，只有此前显式授权且未取消的任务可以恢复。

- [ ] 用户显式取消和退出密室使相关任务授权失效，停止网络、清理无用临时密文与检查点；不能因再次解锁而自动复活已取消任务。

- [ ] 胶囊订阅任务事实，暂停时停止处理动画并显示真实原因；返回后直接显示最新状态，沿用任务 4 的状态合并，不补播后台积压过程。
