## 现状与已确认修复

共同根因是`beginNativeHandoff`与`armSystemSurfaceHandoff`在API调用前启动遮帘，且window.blur无条件先遮蔽。因此既有麦克风权限、普通复制等没有系统弹窗的路径也可能闪出遮帘。发送按钮只有34px范围，输入栏空白未保持焦点，移动时整栏pointer-events:none还可能使点击穿透。发送下方误点至真机失焦的精确链路尚未复现，不把静态推断写成已证事实。

| 入口 | 本次处理 |
| --- | --- |
| 聊天图片、拍摄、文件；保险箱上传；本地备份导入 | 原选择器入口登记原会话/epoch及五分钟上限，无预遮蔽；有效可见失焦保持页面，选择/取消与实际回焦结算 |
| 长按语音、继续录音；音视频通话媒体权限 | 同一有界交接，三十秒绝对期限，旧授权音轨不能复活 |
| 复制消息、邀请/恢复码/入口；分享及系统确认 | 统一六十秒原期限、1.5秒结果后回焦边界；重叠操作共用未结算owner且不延长 |
| 文件/图片下载、备份与诊断导出；通知权限 | 接入同一系统操作交接；没有有效owner的导出失焦继续锁定 |
| 输入栏发送圆钮、底部空白及键盘移动 | 圆钮34px外观不变，伪元素扩大有效命中至44px；空白不提交且保持已聚焦编辑框；移动中吸收指针/点击 |
| 键盘原生栏、未知失焦、网关及管理验证 | 保留既有遮蔽和认证边界；Safari原生栏不属于网页DOM，不能由应用空白区接管 |
| 原生视频全屏 | 现有原生策略保留，纳入回归；真实系统失焦/缩略图须另以设备取证 |

已确认取舍：系统面板未完全覆盖页面时，下方可能仍看到聊天；工具归属是应用证据，不能认证浏览器失焦原因。hidden、pagehide、freeze、显式锁定、空闲/交接到期始终覆盖例外，检查单调和墙上时钟。未知失焦仍立即遮蔽且普通focus不揭开。API结果不能进入另一会话，原消息ID、加密待发箱、草稿、原字节与空间绑定保留。
