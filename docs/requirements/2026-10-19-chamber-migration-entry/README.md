## 现状与修复

1. 旧空间「设置 → 备份数据」打开本地备份页，迁移按钮只在兼容备份页；原端到端测试直接调用私有渲染方法，未覆盖普通用户从设置进入。
2. 在正常设置列表加入「旧空间迁移」，未绑定个人身份或仍有staged迁移的当前空间可见；身份绑定后继续可见，切换成功后与新Chamber密室均不显示。
3. `#legacy-backup`原来只在旧备份页的返回处理中移除；已绑定身份会进入另一备份页，其返回又经过openSession重新命中片段，形成循环。现在在合法进入备份路由时一次消费该片段，保留路径、查询参数和history state，之后使用正常页面返回；锁定时仍先验证，其他邀请／恢复片段不变。
4. 原设备、原空间与原浏览器继续使用现有迁移。双根历史共同解密、逐记录／原附件／投影落盘回读、两份完整性回执、相同安全码与双方最终确认均保留；不清空历史，不创建新空间，不跳过待发／快照一致性检查。
5. 实际桌面返回后还发现`spaceDrawerOpen`保持true，而页面已回聊天、没有设置节点且无退出动画；再次点击设置因此被旧标志阻断。桌面设置关闭时清除该标志，沿用其他关闭分支的状态语义。

首轮测试夹具误点桌面隐藏的关闭图标，改用已有可见返回控件；之后一次等待关闭动画的假设仍被回读状态否定。保留失败记录，按真实`drawer=true / settings=false / surface=chat`证据修复桌面状态，不强制点击、不跳过设置入口或弱化迁移断言。
